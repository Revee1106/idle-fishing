# 16｜核心计算与配置接口详细设计

依赖：05、10、15、contracts.ts。所有函数在同一份共享核心实现。此处给出 E01—E09 推荐算法；参数来自 GameConfig，无隐式正式默认值。示例仅测试。`cfg` 指已验证配置，`cast` 使用其锁定版本，`current` 指操作时生效版本。概率计算使用有限 number，业务整数遵守15；各函数先验证引用和输入域，再计算，再验证输出，不允许从错误路径继续生成收益。

## 1. 数学及采样工具（内部函数）

| 函数 | 输入/输出 | 精确算法 |
|---|---|---|
| ratio(A,K,D=1) | Nat,正数,正数→[0,1] | A=0返回0；否则 A/(A+K*D)，先算 1/(1+K*D/A) 防中间求和溢出；A不可有限表示时用BigInt位数比较近似并验收，当前技术门禁先 NUMERIC_LIMIT，不隐式返回1 |
| lerpCurve | Piecewise,x→number | x小于首点取首y，大于末点取末y；中间两点线性插值；x严格递增且非空 |
| clamp | x,min,max | min<=max，min(max,x) 后 max(min,...)；显式0禁止项在clamp前返回0 |
| weightDraw | 有序正权列表,U→条目 | 按稳定ID/明确枚举序排序，累加前先除最大权重防溢出；选择首个累计和严格大于 U×总和的条目；舍入导致落到末尾取最后一个正权项；全0返回无候选；U必须[0,1) |
| probabilityDraw | p,U→bool | U<p；0永不，1必定；包括p=0或1也按调用契约消耗固定逻辑抽样（CoreApi本身只接收已抽样值） |
| roundMicro | x→Nat | 正浮点x转工作微单位时 round(x×10^6)，非零但舍入0时按指定通道规则取1；不得对业务时间每一分片重新取整 |
| ceilDiv | Nat a,Nat b | `(a+b-1)/b` BigInt，b>0 |

`U` 来源见19；不是包含1的 Ratio，接口验证必须拒绝1用于随机输入。候选归一化先排序再以固定顺序求和，不从对象枚举顺序抽样。环境、鱼种、等级、颜色分别计算；计算概率不推进随机状态。稀有度及重量档固定枚举顺序见 contracts.ts。

## 2. M01 effectiveStats

入参 initial、allocated、rodBonus 五项均存在，非负Nat；逐项 BigInt 加法，返回独立 Stats。`effective = initial + allocated + currentRodBonus`。未分配点、等级、装备历史和广告不进入。角色作用曲线 `F=A/(A+K*D)`；时间缩减 `1-maxEffect*F`；幸运倍率 `1+(maxMultiplier-1)*F`；K各通道独立。常规竿luck必须0。属性点不存在可重复累计的持有装备加成。

## 3. M02 admission

`admission(state, selection, config)` 纯读取。检查顺序：地区ID存在/解锁→位置存在、enabled且属于地区、隐藏位置已发现→竿/线/饵存在及所有权→各自使用条件→距离与深度≤竿上限→线长几何约束。FREE视为已拥有；CONSUMABLE 的拥有检查仅检查可合法使用/已解锁（不检查库存）；REUSABLE必须拥有。`requiredLineM = hypot(D,H)`，`effectiveLineM = lengthM*(1-reserve)`；比较原始值，等于上限合法。返回所有可判定原因，按上述顺序去重；缺失定义导致无法计算的长度字段填0并带NOT_FOUND，调用方不得当作准入通过。`allowed = reasons.length===0`。不校验余额、仓库、硬拉力或动态天气，不读随机。结构性鱼饵适配由额外检查 `hasStructuralCandidate`：忽略暂时天气/事件/时间条件、保留常规及合法可到达的临时种群定义，考虑鱼种偏好和合法重量档；实际空池由M04处理。选位非法不能自动改位置。

## 4. M03 时间接口

统一每毫秒工作量单位：动作所需工作= `round(clamp(baseMs,minWorkMs,maxWorkMs)*1e6)`；推进时每毫秒速率`R=round(speedMultiplier*1e6)`，配置的 maxRateMicro 是上限（至少1e6）；准备、抛竿、收线同速率。以 BigInt 累加 `done += dt*R`，达到阈值时夹到该阶段 required，额外工作不带入下阶段；禁止逐步浮点积分。时间事件候选 `dt=ceilDiv(required-done,R)`，如有最小现实时间门槛取二者max。工作、activeMs及emptyMs仅在实际可推进的时间累计，暂停或额度外不累计。每个阶段在实际阶段事件处量化一次，不在 UI tick 重算阈值；速率只在环境、广告或有效候选条件变化时更新。阶段最大实际时间由 `maxActiveMs` 定义，配置需保证非等待阶段所有允许基础工作及最小现实时间可在正常速度内完成；违反为 CONFIG_INVALID，不强制成功。

### castWork(cast,cfg) → Nat

`base=(rod.castBaseMs+rod.castMsPerM*distanceM)*(1-agi.maxEffect*F(AGI,K))`。返回clamp后微工作。抛竿开始时已扣饵，完成才进入等待；无抽样。准入使用实际距离，不能按远投档固定距离替代。

### waitDemand(U,cfg) → Nat

三角分布：`c=(mode-a)/(b-a)`；U<c 时 `Q=a+sqrt(U*(b-a)*(mode-a))`，否则 `Q=b-sqrt((1-U)*(b-a)*(b-mode))`；a=b=mode时直接Q=a。`required=max(1,round(Q*1e9))`，等待采用与动作不同的无量纲纳工作单位。a>0，a<=mode<=b，均值1（容差1e-9）。进入等待抽一次，保存 required、done=0、activeMs=emptyMs=0。

### waitRate(cast,distribution,cfg,speedMultiplier) → Nat

空池返回0。`signal=rod.sensitivity*w+line.signal*(1-w)`；`signalFactor=1-signalMaxReduction*signal`；`perceptionFactor=1-maxEffect*F(PER,K)`；`meanMs = position.biteBaseMs/(activity*bait.attraction)*perceptionFactor*signalFactor`；meanMs 必须有限正；`rate=max(1,round(1e9/meanMs*min(speedMultiplier,maxRateMicro/1e6)))`。若dist非空但活动度为0，返回0并视为空池（有效候选活跃度0）。幸运、敏捷及鱼种总权重不影响速率。等待完成需 `done>=required && activeMs>=minRealMs && 有效候选且活动>0`；已达需求但当刻变为空池，保留完成工作量，直到恢复。空池累计有效现实时间emptyMs，达到emptyTimeoutMs或activeMs达到wait.maxActiveMs仍未满足咬钩条件则 EMPTY；同时达到需求并有有效鱼池时咬钩优先。广告不加快现实硬超时。等待 `minWorkMs/maxWorkMs` 不适用于无量纲需求（Schema要求两者0，禁止混用），`minRealMs<=maxActiveMs`。空竿无鱼/无失败XP；不为了空竿强制抽意外事件。

### 捕获基础收线及准备

基础收线 `T_basic=(reelOperationMs+1000*requiredLineM/reelBaseMps)*(1-reelAgility.maxEffect*F(AGI,K))/rod.reelEfficiency`；基础收线至少1毫秒。额外对抗见M06；完整收线工作按fight上下限夹取，按原比例拆分基础/额外；若extra=0仍完整执行节点。`prepareWork`: 选择 failure 对应 prepareMs，未失败使用 outcome 对应值，乘敏捷缩减并clamp，返回动作微工作；失败不扣额外金钱或装备。

## 5. M04 distribution 与环境候选

入参 cast+ModelContext（锁定版本和当前世界投影）+只读条件状态。输出候选及概率、等级权重、体色概率、聚合活动；仅供引擎/模拟器，不直接向正式UI返回。步骤固定：

1. 取当前position的常规种群，叠加有效洄游 TEMP_POPULATION。对同一鱼种重复定义拒绝配置重叠；有效期内临时种群可加入不存在的鱼种，不重复追加常规鱼种。按 population.id 排序。
2. 排除条件不满足、baseWeight=0、环境显式禁止、鱼饵鱼种偏好=0。偏好取地区鱼种覆盖→鱼种→食性→default，首个存在键即返回（0有效）。环境每通道=昼夜×天气×按稳定eventId的有效事件因子；缺通道=1；任一0返回0，不做下限复活。否则按通道 bounds clamp。
3. 每个重量档原始 `gradeWeight = species.band.baseWeight * (pop.gradeMultipliers[grade]??1) * (bait.bySpeciesGrade[species][grade]??defaultByGrade[grade]) * gradeEnv * luckMultiplier`。先排除0，再归一；全0排该鱼种，不重新抽样。幸运普通等级倍率可配置1。
4. `H=1-stealthMaxLoss*wariness*(1-line.stealth)`；`W=pop.baseWeight*baitPreference*H*speciesEnv*luckRarity`。W=0排除。各鱼种正权概率归一化。
5. 体色仅从 species.colors 构建；`Wc=baseWeight*(pop.colorMultipliers[color]??1)*colorEnv*luckColor`；normal保持正权，禁止0或被环境禁止；normal幸运倍率恒1；未配置特殊色幸运倍率=1（显式中性默认）。归一后特殊色总概率S若>S_cap，所有特殊色乘S_cap/S，normal概率=1-S_cap。0不复活。
6. 活动度用通过前述结构过滤的种群的**基础权重**加权平均 `baseActivity*activityMultiplier*activityEnv`，不用鱼饵相对偏好、隐蔽或幸运乘数。为防隐蔽/幸运数值改变活动，不得因为它们的倍率变化改变活动集合；若隐蔽H=0则定义其为不适配硬排除并配置校验stealthMaxLoss<1。最终非零活动按activityBounds夹取；活动0时等待速率0。若总权0，输出empty=true/activity=0/candidates=[]。

注意候选条件读取抛竿快照的等级、装备、饵、位置，以及该时点环境；全局持有/发现等条件按当刻状态评估；若等待中玩家命令改变条件有效性，先推进旧速率至指令时间再重算。未完成鱼的概率/重量不得泄漏。`individual` 使用已经计算的候选 grade/color 分布，不得重新归一不同版本数据。

## 6. M05 individual / combat

`individual(candidate, draws, id, at, ctx)`：固定3个逻辑随机数 grade、weight、color；先按档序TINY…RECORD抽档；档[a,b]内 `w=a+floor((b-a+1)*pow(U,alpha))`，极端浮点舍入只夹到[a,b]。验证离散抽样有限分辨率：每个整数区间逆CDF跨度至少 `2^-53`（重点验证两端；单调幂函数的最窄区间在端点）；不满足拒绝配置，而不是假称所有整数可达。U=0必须得到a；理论b要有非空U格点可达。颜色按稳定ID抽取，独立于重量。返回 PlannedFish 锁定id、鱼种、种群、重量、档、色、咬钩时间及环境。此时不添加持有鱼或档案。鱼ID候选由本尝试唯一派生，不再额外生成。失败只显示大类，不解锁图鉴或确切重量。

`combat(fish,cfg)`：wRef为combat.referenceG或species.referenceG，`Fs=sustainN*pow(w/wRef,sustainExponent)`，`Fb=burstExtraN*pow(w/wRef,burstExponent)`；hookDifficulty、errorDifficulty、errorExtraForce、fightBaseMs 曲线x统一实际整数克，线性插值；难度严格正、额外拉力非负、时间非负。体色不影响。相同鱼种同重量同版本得到相同属性。

## 7. M06 capture

输入5个固定逻辑抽样（strength,hook,error,strengthAt,hookAt），无论某项概率为0/1也抽满；无额外全局成功抽样。`Ds=(Fs/forceReferenceN)/rod.control`；`Fstr=ratio(STR,strengthK,Ds)`；`Pstrength=clamp(strengthMaxRisk*(1-Fstr)^strengthGamma,0,1)`；`Phook=clamp(baseHookRisk*(1-hookSkill.maxEffect*ratio(SKILL,hookSkill.k,Dh))*pow(rod.control,-hookControlExponent),0,1)`；`Perror=clamp(baseErrorRisk*(1-errorSkill.maxEffect*ratio(SKILL,errorSkill.k,De)),0,1)`。额外对抗 `T_extra=fightBaseMs(w)*(1-fightStrength.maxEffect*ratio(STR,fightStrength.k,Ds))`，控鱼只经Ds进入该路径一次；与16.4基础收线合并为totalWork，baseWork+extraWork=totalWork。

`Fpeak=Fs+Fb*(1-line.burstBuffer)`；`Factual=Fpeak+extraForce(w)`仅操作失误。若Fs或Fpeak超过竿或线限，physicalPass=false；否则true。超载判定 strict `load>cap`，等于合法；两者都超取较低cap，同cap取LINE（E02），具体失败为PHYSICAL或OPERATION。理论成功率物理失败0；否则 `(1-Pstrength)*(1-Phook)*(1-(operationWouldOverload?Perror:0))`，只用于经验及模拟。

节点总工作位置 `floor(totalWork*progress)`（progress先量化百万分数，使用BigInt）；持续和爆发必经节点始终存在，操作失误抽中则在爆发同位置追加操作检查（即使未超载也不失败）；力量/脱钩抽中时节点位置 `lo+(hi-lo)*Uat`；COMPLETE固定在totalWork。节点同位置：SUSTAIN→BURST→OPERATION→STRENGTH→HOOK→COMPLETE；若一个现实毫秒跨多个工作节点，先按节点work再按上述顺序执行。所有正常必经节点需在成功前执行。执行遇到首个failure立即终止，剩余不触发、不计统计；若 COMPLETE 同刻和失败，以失败优先。成功还须达到fight.minRealMs；失败不受最小成功耗时限制。节点生成时固定失败与负载，执行只读、不再抽样。理论物理失败即使早脱钩，失败XP仍0。替代事件无真实鱼，另走18特殊回收，不调用capture。

## 8. M07 xpNormal / xpSettlement / grantXp

`xpNormal`: `baseXp * clamp(pow(w/wRef,xp.weightExponent),min,max)`，按15成功四舍五入最低1。`xpSettlement`: CANCELLED/EMPTY=0；REPLACEMENT鱼类XP=0，仅事件奖励独立发XP；FAILURE仅当fight.physicalPass，`floor(min(failXpCap, xpNormal*failRatio*F_progress*pow(successProbability,capabilityExponent)))`，其中F_progress=失败节点work/totalWork而非实际秒；用一次倍率量化并向下，不含体色/首次/纪录，不设保底；上限精确比较BigInt。

SUCCESS：常规XP+`round(xpNormal*color.xpBonusRate)`；flags由结算前历史判定；首次鱼种/地区/特殊体色按各自配置一次性奖励（normal无首次颜色额外XP）；普通全局每鱼种最大纪录奖励需要已有记录且新最大、满足 E05 阈值。首次记录设置rewardBaselineG=w，不发普通刷新奖励；后续只有发奖更新baseline。重量档里程碑按配置LARGE/GIANT/RECORD及达到的更低档逐个补齐；唯一键 `['milestone',speciesId,grade]`。返回 parts 分项、total、新claimKeys及recordBaselineG，状态未修改。历史键已经存在则不得重复发；flags/record必须由事务生成而非玩家传入。失败不能触发捕获首次或里程碑。

`grantXp`: 原XP加本次amount，totalXp增加；while xp>=next(level)，减去需求、level+=1、unspent+=当前配置pointsPerLevel、totalPointsGranted同步增加；`next=ceil(A*pow(level,B))`≥1；maxLevelUpsPerTransaction为异常保护，达到上限且仍有升级则返回NUMERIC_LIMIT并整笔不提交，不截断经验，不丢等级（参数需覆盖合理最大单事务）。输出新level/xp/total/unspent/totalPointsGranted/levels；应用层更新累计点及发事件。永久离线额度由等级对应tier求取，不增加已锁会话额度。禁止地区/等级衰减或广告直接XP。

## 9. M08 salePrice / resetCost / replenishQuote / offlineGold

- `salePrice`: 找当前有效配置的species及color（若已停用，仍保留历史定价定义，不允许直接找不到或变价为0）；`baseGold * pow(w/priceRef,exponent) * color.priceMultiplier`，一次倍率量化，四舍五入后max(minSaleGold)。不看稀有度/等级/纪录/捕获地。不在捕获时提前入账。所有渠道同公式。
- `resetCost(paidResets)`: 当前已成功金币重置次数n，费用 `min(cap,round(initial*R^n))`；E项建议R使用安全整数且>=2（暂定2）；从initial开始，以BigInt乘R并夹到cap，至多迭代至首次达到cap或已执行n次，取较小者；R及cap均为配置，禁止浮点对数和溢出。n巨大也不循环到n。不与等级相关。免费/广告重置不改变n。回本只为模拟工具：增量<=0则无有限回本期。
- `replenishQuote`: unit>0；`available=max(0,balance-reserve)`；`quantity=min(batch, floor(available/unit), max(0,limit-stock))`；`cost=quantity*unit`。返回0不扣款；仅合法已解锁消耗饵，单价取当前可买offer；参考价用于统计而非扣现金。
- `offlineGold`: `eligible=max(0,newFishAutoSaleGold-consumedBaitReferenceGold)`；`reward=min(cap,round(eligible*goldRate))`；报告结束时锁值和版本，领取不重算库存/价格。报告已领或过期不能发。额外金币不复制鱼/XP。

## 10. ConfigApi.validate/inspect 和版本解析

`inspect(raw)` 返回稳定按path/code排序的全部可判定issues；`validate` 有ERROR则CONFIG_INVALID（调用方可另取inspect），否则返回深冻结、完整配置；WARN必须记录。加载次序：JSON结构/必填及额外字段（拒绝未知字段）→类型/范围→ID主键和外键→图引用/条件作用域→语义不变量→可达性和保底。`experiment=true`只允许测试/模拟，正式构建拒绝。`VersionResolver.get`按三个版本精确取包，禁止找不到时返回current；`current`仅指已通过校验并完成切换的包。

必须编写运行时 JSON Schema：每种discriminated union使用oneOf+const；所有 object additionalProperties=false（Dict允许合法ID的键，值Schema严格）；数值范围同15/16；数组ID无重复、必填无隐式默认。缺省仅本文件明确的中性倍率、可选引用、未配置特殊奖励=0；不得由空JSON补齐正式数值。具体检查：

| ID | 语义检查 |
|---|---|
| CFG01 | 所有ID和字典key等于对象id，外键存在，停止销售不删除历史定义；无特殊竿普通商店/广告入口，无普通竿luck |
| CFG02 | 初始池塘/位置/竿线饵合法，唯一FREE且参考价0、无限使用，至少一种可捕获普通鱼；常规位置无永久空池，允许已定义会恢复的临时空池 |
| CFG03 | 六档完整连续闭区间、weightRef>0、理论端点可抽；normal色正权及售价1/XP0，颜色及重量各通道非负；事件不得复活显式0 |
| CFG04 | 物理、速率、时长、曲线参数合法，时间非零边界、triangle均值1、节点比例排序、所有正常阶段在maxActiveMs可完成；配置不能引入零时长循环 |
