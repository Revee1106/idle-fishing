# 13｜AI开发规范与验收门禁

状态：Code First及自动化方向已确认；以下具体工程规范为推荐实施契约，命令与工具尚未建设。

## 1. Cocos Code First

保留最小Boot场景、Canvas、Camera、启动组件及必要资源/构建设置。业务节点、布局、事件、页面切换、动画以TypeScript动态创建，避免人工拖拽绑定业务页面。具体视觉由其他AI交付；本阶段不设计正式UI，不使用额外Web正式表现层。优先Cocos 3.8 LTS，版本、构建所需GUI、编辑器安装、微信开发工具和真机均在Spike验证，不声称已能无头构建或零人工。

建议结构：assets/scenes/Boot.scene、scripts/bootstrap、ui/components、ui/layouts、ui/pages、ui/theme、state、animation、platform、resources。轻量共用按钮、文本、图片、容器、布局、滚动列表、虚拟列表、弹窗、Tab、进度、Toast、Loading。按真实业务需要增量实现，不为组件库而造组件库；不要为未来需求先造通用游戏框架。资源引用通过稳定资源ID及统一管理，不手工修改生成的序列化产物。

UI读核心状态投影，发送指令；不得直接改业务状态，不从动画回调发奖，不在页面计算概率、售价或经验；无业务数值硬编码。页面销毁取消订阅/动画/监听，长期切页不增加后台任务（建议测试）。

## 2. AI交付流程

需求基线 → 明确单个任务及验收 → 实现/测试 → 运行构建及回归 → AI独立代码审查 → 修复并回归 → 用户必要真机/视觉验收。用户主要决策、真机及视觉确认；AI承担代码、配置、测试、脚本、报告和修复。可用现有Codex工作流，不要求额外开发一个专用Harness框架。

每次任务开始列出依赖文档和未决项；发现玩法冲突停止该部分并提交决策，不自行补齐需求。可以选择不影响玩法的实现细节但须记录。任务只实现授权范围，不顺手改其他系统；配置暂定值须明确标记。

建议建立根目录AGENTS.md（索引而非复制全部策划）：核心不依赖wx/Cocos/Node IO；生产和模拟器共用源；统一指令；规则数据驱动；版本锁定；禁止服务器/IAP；本地防作弊限制；任何新增功能含测试；已知风险和失败证据不得隐藏。

## 3. 自动化命令建议

| 命令 | 职责 |
|---|---|
| npm run typecheck | 类型检查 |
| npm run test | 规则单元、集成、回归 |
| npm run validate-config | Schema及业务约束 |
| npm run simulate | 固定种子或批量实验 |
| npm run build:web | Cocos Web构建 |
| npm run build:wechat | 微信小游戏构建 |
| npm run test:e2e | Web实际交互/状态断言及截图 |

实际脚本可用workspace/npm或经验证的其他方案；不得把尚不存在的命令当作成功。记录工具版本、构建命令、日志、退出码、产物路径。需要人工初始配置时给一次性明确步骤；真实平台或设备不可访问时标记阻塞，不虚报结果。浏览器截图不是微信真机验收替代品。

## 4. 测试与门禁

- 核心单元测试：公式边界、零权重、整数取整、硬限制、无负余额、唯一所有权。
- 状态机集成测试：同刻事件、取消、补货、满仓、奖项连锁、离线与在线/批次一致性。
- 持久化故障测试：写入前、部分写入、写入完成未确认、确认后退出、重复回调、备份损坏与迁移失败。模拟与真机结果分别记录。
- 数值验证：种子、配置、引擎、策略版本可复现；平均、百分位、异常及原因。无完整模拟时不冻结数值。
- 构建及平台：共享源码Node/Web/微信兼容，资源大小、启动、存档、前后台及真实广告。
- 视觉：AI可通过浏览器截图和交互日志迭代；用户只在确需真机与正式视觉时介入。具体适配设备及性能阈值待验证。

交付报告建议包含：完成范围、变更文件、命令和真实结果、失败与未跑项、待决事项、实际人工操作清单、风险及下一任务。未测试不得标PASS；核心硬规则失败不得进入下一阶段。用户确认设计并不代表确认实际实现。
