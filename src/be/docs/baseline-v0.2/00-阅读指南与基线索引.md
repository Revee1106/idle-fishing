## 2. 状态定义

- **已确认**：用户认可的功能范围、职责划分、硬性约束或计算模型结构。变更需要重新评审。
- **暂定**：讨论中的初始配置、内容候选或验收目标；可作为模拟起点，不作为正式发布常量。
- **待定**：尚无唯一确定规则，须在相应设计或开发前明确；不得擅自当作已确认需求。
- **后续**：不属于首版必需范围；不得因技术方便擅自提前加入。

本文档套件是截至归档日期的整理版，不等于已经通过数值验收、技术设计或开发验收。示例表格不具有高于规则的优先级。

## 3. 已确认的关键修订（以最新规则为准）

| 事项 | 当前规则 |
|---|---|
| 商业化 | 不开放内购；仅自愿激励视频，不强制广告 |
| 属性重置费用 | 随累计**金币重置次数**递增并封顶，不随等级增长；新手免费和广告重置不增加该计数 |
| 离线金币广告 | 按本次离线自动出售新鱼收入减去实际消耗鱼饵的参考价值计算正净额；不是按补货现金支出扣减 |
| 失败经验 | 有比例及绝对上限，可为0；客观不可捕获时为0，无正数保底 |
| 装备 | 永久拥有，不强化、不损耗、不维修、不出售；改装仅为后续方向 |
| 幸运加成 | 普通鱼竿不能加幸运；部分特殊鱼竿可加幸运；只有装备中的鱼竿生效 |
| 离线额度 | 初始8小时、最高24小时；会话开始锁定额度，期间等级增加的永久额度下次生效 |
| 水族馆 | 只收藏、展示实际捕获的鱼；不养成、不产出资源，不设置私人鱼塘 |
| UI | 竖屏、治愈插画风；具体UI设计由其他AI负责，本套文档不做页面布局 |
| 技术 | Cocos Creator + TypeScript Code First；优先3.8 LTS，具体版本待真机验证；Node模拟器共用核心 |
| 存储 | P0纯本地文件、多槽备份、迁移、幂等；P1云备份、账号绑定、跨设备恢复、可信时间；P2服务端权威 |
| 结算 | 12号文档统一事务顺序；满仓保护单鱼待处理；备用基础饵不自动切回；版本以本机首次加载为切换边界 |

## 4. 文档使用约束

开发者应首先理解01、05、08、09，再阅读所负责的功能文档。模型05是计算结构的主要依据，其他文档解释业务职责；若出现规则冲突，应提出差异并确认，不得以示例数值覆盖规则。所有概率、价格、成长系数应配置化并带版本；正式游戏和模拟器复用同一核心引擎。技术路线以11—13为准，逻辑契约以10和12为准；09仍待决的细节不得作为已确认规则。初期不建设数据库或HTTP后端。14号任务书仅授权技术验证范围的建议，不能视为已实施。
