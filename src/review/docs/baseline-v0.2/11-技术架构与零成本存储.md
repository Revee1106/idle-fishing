# 11｜技术架构与零成本存储

状态：技术路线已确认；工具链版本、平台能力、具体接口及性能尚待技术验证。适用首版P0，不代表已有可运行代码。

## 1. 约束与演进

一人公司、AI为主要开发主体。初期不购买服务器、数据库、云函数、CDN；采用纯客户端计算和微信用户文件存档。0元指存储及自建后端基础设施，不代表平台认证、发布、推广或美术等费用为零。

- P0：本地存档、多槽恢复、迁移、单本地有效任务、离线补算、重复结算保护、删除二次确认、全局统计、存储适配接口。无需云端登录即可运行核心玩法。
- P1：账号云端绑定、云备份、跨设备恢复、可信时间；优先解决换机数据丢失。远程运营监测方案另定。
- P2：权威计算、竞争性排行榜和比赛。不能将本地数据直接视作可信竞技成绩。
- 微信本地缓存只用于非关键小型数据；主档采用 FileSystemManager 与 USER_DATA_PATH。微信托管用户数据不是完整存档数据库；后续可研究社交显示。云开发或自建后端等到确有需求再评估。
- 本地文件与本地时钟均不可信，校验和只是检测损坏；换机、清除微信数据、卸载或手机损坏无法保证恢复。正常故障保护不能宣称彻底防篡改。
- 存储空间、写入语义、分包限制、广告开通资格及费用政策必须由开发者工具、控制台和真机验证；不将历史调研中的10MB/200MB等参考值作为验收事实。

## 2. 技术路线

Cocos Creator + TypeScript Code First，优先3.8 LTS，确切版本在Spike锁定；Node.js + TypeScript运行独立模拟器；Git单仓库。JSON作为配置推荐格式、JSON Schema和语义校验作为工具方案；Vitest为优先测试框架，具体工具版本和打包方式待验证。不引入额外uni-app/Phaser正式表现层，不建设数据库表或HTTP接口。

| 层 | 责任 | 禁止依赖 |
|---|---|---|
| contracts | 稳定ID、状态类型、配置契约、指令与事件 | Cocos、wx、Node IO |
| game-core | 八模型、事件驱动状态机、环境、随机、成长、收藏、经济 | Cocos、wx、Node IO、真实系统时钟、Math.random |
| game-config | 配置解析、校验、版本清单；平台读取由适配器注入 | UI状态、业务状态修改 |
| game-application | 指令串行、逻辑事务、时间推进、持久化协调 | 具体平台API、页面组件 |
| game-client | Cocos表现、代码UI、平台适配 | 自行重算或修改核心业务状态 |
| simulator | 自动策略、虚拟时间、实验配置、报告 | 另写游戏算法、绕过合法指令 |

建议依赖方向：client/simulator → application → core/contracts；config提供已校验规则输入。共享包必须只有一份业务源码，禁止手工同步两份。Cocos若不能直接解析workspace包，可由自动构建生成兼容模块；产物可重复生成且标记来源，不允许直接编辑产物。具体编译目标和模块解析以Spike为准。

```text
idle-fishing/
  docs/
  packages/{contracts,game-core,game-application,game-config}/
  apps/{simulator,game-client}/
  config/{rules,content,scenarios}/
  tests/{unit,integration,regression,fixtures}/
  tools/
  reports/
```

目录名为建议，不要求空目录或过度拆包；若调整需说明且保持上述边界。

## 3. 核心及平台契约

八模型输入输出见05、10；纯计算尽量无副作用；随机输入与配置显式传入。环境、图鉴纪录、发现成就、库存等模块在应用层事务内协调。运行时只维护一个有效状态，通过领域指令修改。UI读投影/订阅，不直接改金币、经验、鱼获或随机数。

| 适配接口 | 微信 | Node模拟 |
|---|---|---|
| SaveRepository | 本地文件多槽 | 内存/文件 |
| ClockProvider | 设备时钟＋前台单调计时（能力待验证） | 虚拟时间 |
| AdProvider | 微信激励视频回调 | 模拟结果 |
| LifecycleProvider | 前后台事件 | 计划登录退出 |
| ConfigProvider | 本地资源包 | 配置目录 |
| TelemetryProvider | 本地有限统计、诊断 | 实验报告 |

逻辑接口建议：`load` 区分不存在、有效、损坏、版本不支持；`commit(state, expectedRevision)` 返回持久化结果及revision；`recover`、`clear` 支持错误区分。不得把损坏当作新玩家。未来替换存储实现仍需设计账号身份、并发冲突、授权及信任边界，不是只替换一个类即可。

## 4. 时间与随机

统一 `advanceUntil(state,targetTime,context)` 概念接口，以事件边界推进，不逐秒补算。等待积分、环境边界、广告到期、对抗失败、会话截止按12执行。在线、离线、模拟同代码；可分片运行避免阻塞主线程，分片大小不影响最终业务状态和随机状态。动画只展示，不触发奖励。

随机使用可持久化的确定性PRNG；鱼种/等待、重量/体色、对抗、环境、个人事件应分流，具体算法、种子派生、数值精度、流划分粒度见09 D12。保存随机状态和已抽取的待执行节点；跨进程及跨运行时验证。禁止核心使用Math.random或直接读取Date.now。报告记录种子、策略、引擎和配置版本。

## 5. 本地持久化

三份轮换存档，包含schemaVersion、configVersion、engineVersion、revision、完整业务状态、当前尝试、随机流、时钟/会话、已结算标识、报告累积器、校验和。可选临时文件与索引仅作辅助；启动扫描有效槽，不依赖唯一索引。校验包含序列化完整性和基本业务不变量。格式及校验算法待Spike确认。

提交：构造一致候选状态 → 写非当前有效槽 → 重新读取并验证 → 确认提交 → 更新重要奖励表现。至少保留此前有效槽；不假设文件重命名具有数据库级原子性；写入失败不得将未提交的重要变更展示为已保存。崩溃后优先最高有效revision。若出现写入结果不确定，先扫描确认是否实际提交，再处理重试（实现建议，具体协议需故障注入验证）。

普通鱼获、自动出售等可批量存档，暂定30秒（实际性能待测）。首次发现、特殊体色、重要纪录、特殊装备、购买/解锁、属性调整、手动交易、收藏、广告奖励立即保存；离线分段检查点及最终保存；后台尽力保存，不依赖回调必定成功。未提交的普通进度可能重算/损失少量，不承诺绝对零数据丢失。已提交金币、消耗、时间和随机状态必须同版本一致，禁止分别持久化。

启动：验证包和存档 → 选择最高有效槽 → 迁移（保留旧档）→ 恢复未完成会话 → 正常运行。所有槽损坏或迁移失败时不覆盖；提示恢复/明确删除。删除确认及备份防复活需详细测试，见09 D14。保留重要鱼类档案；普通已售明细汇总并安全清理，防止无界增长。

## 6. 版本

SchemaVersion负责结构迁移，ConfigVersion负责数据参数，EngineVersion负责计算语义。P0不知晓远端实际发布时间，以本机首次成功加载新版本时刻为切换边界：此前离线用旧版，跨边界正在进行的尝试保留原规则，新抛竿采用新版本。环境变更由旧尝试解释当前世界时间，具体映射待D09；未售鱼按出售时有效价，已结算不追溯。

保存或随包提供必要旧规则/配置，跨多个版本更新也不能静默用新版重算。版本兼容实现、留存策略、缺失旧版本的安全恢复方案待设计。发布前用真实旧档和未完成尝试验证。迁移失败保留旧档，不跳过收益而假装一致。

## 7. 资源与成本

本地资源包及微信分包优先，按实际包体和资源清单验证。美术由其他AI负责，UI采用代码生成；不先购买远端资源托管。若无法在平台限制内发布，报告具体包体和备选方案再决定。可评估手动存档导入导出（非P0承诺），不冒充云同步。
