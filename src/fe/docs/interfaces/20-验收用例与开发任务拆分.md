# 20｜接口验收用例与开发任务拆分

版本v0.3-draft。验收对象：本套接口设计及既有v0.2基线。所有示例是测试夹具，不是正式游戏数值。测试必须可自动运行，真正微信平台相关项另有真机证据。此文档不是已经执行的测试报告。

## 1. 测试运行约定

所有业务测试固定cfg、初始state、时间线及rootSeed；除明确故障注入/压力初始化外，所有写状态通过正式接口。断言不仅比较返回码，还比较完整状态差异、余额/库存、时间、奖励键、RNG、版本和归属；纯函数断言输入不变。每条失败路径至少断言没有该命令导致的资产变化（此前合法时间推进可以变化）；每条重要成功路径断言已持久化后才发布确认。对在线/离线比较，先统一输入和有效作钓时间，不比较会话报告/存档revision/命令回执等本来不同的元数据；核心结果、统计、随机流、游标、持有及金币必须一致。分片比较不排除任何随机流或业务资产。测试注入random U仅用于单元测试；集成测试必须走正式PRNG。

报告标准：PASS/FAIL/BLOCKED/NOT_RUN，记录testId、命令、退出码、工具版本、fixture版本、seed、实际断言、日志路径、平台及设备。任何必需项未执行不能标PASS。自动化断言必须能在失败时返回非0退出码，禁止只输出“测试通过”文本。

## 6. 数值模拟器接口及输出

`SimulatorApi.run(request)`：验证scenarioId、mode、configVersion、seedStart（uint32）、seedCount>0且seedStart+seedCount-1<=2^32-1、durationMs>0、登录/采样时间相对起点单调且在duration内；strategy/adStrategy存在。使用experiment或明确标记的生产配置副本，不读取真实玩家存档，不联网。为每个seed初始化独立fixture和虚拟时钟。FIXED保持选择和属性，不自动购买新装备/分配点；可按该固定策略自动补饵/售鱼。GROWTH从1级使用合法指令，登录计划决定何时加点、购装备/解锁、看广告；离线不绕过玩家指令许可。STRESS可用非法边界输入、故障注入及合成高等级初态，但必须在报告标记fixture来源，不计正常成长统计。普通策略只读ReadApi，理论最优可在实验环境访问CoreApi概率分析但实际动作仍走正式命令。禁止另写近似收益逻辑替代事件引擎。

输出SimulationReport记录版本、种子列表、策略版本、失败trace、blocked；各时点输出等级、累计XP/金币/净金币流、实际作钓时间、捕获次数/失败原因、鱼种/地区/体色发现、重量纪录、装备购入/回本、鱼饵购买/耗值、属性重置/广告权益；以 `metric@timeMs` 唯一键。mean及分位使用每个seed的同一指标；排序后p分位采用nearest rank `index=max(0,ceil(p*n)-1)`；min/max同时记录，不把均值当典型玩家。大整数指标转换到报告浮点前检查范围，超范围保存原十进制原始样本并标记该聚合NUMERIC_LIMIT，不影响引擎状态。报告原始样本JSON、聚合CSV及可复现trace；违规seed保存固定输入和命令时间线。并行执行时按seed顺序归并，结果不得依赖worker完成顺序。不同分片、运行次数及并行度的同seed结果一致。

验收顺序沿用08：单模型→完整钓鱼→新手效率→经验金币→属性收益→成长→随机收藏→广告→长期经济。硬规则必须全通过；数值目标如新手一分钟首次鱼、初始成功率90%、30天主内容成长、成熟重置封顶2—4小时净收益都是待评审目标，不当作已经通过。模拟不能证明游戏一定好玩，仍需真实体验。
