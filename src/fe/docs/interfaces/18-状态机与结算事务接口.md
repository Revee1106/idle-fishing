# 18｜运行状态机与结算事务详细设计

本卷定义 EngineApi、领域事件及全部状态变更。读15—17、19；所有输入 state 不可变，产生候选 state 后检查不变量。核心不直接调用存储；mustCommit通知应用层。下列算法为顺序规范，不需要采用相同代码结构，但不得改变结果、随机调用次数或业务边界。

## 1. 状态初始化

新档仅在SaveRepository返回EMPTY且未发现删除/损坏痕迹时创建，或经19明确删除后用户再次选择开始。playerId、saveEpoch由平台新建本地标识（不是微信openId），rootSeed由平台随机源注入，初始时间来自ClockProvider；测试由fixture注入固定值。初始化level=1、xp=totalXp=unspentPoints=totalPointsGranted=0，allocated五项0，paidResets=freeResetsUsed=0，gold=cfg.initial.gold（统计初始资金与收入区分），拥有初始竿线，基础饵隐式拥有，空消耗库存，初始地区解锁，所有普通位置通过准入而非自动标记隐藏发现；初始仓库/缸位tier，空鱼/档案/成就/发现/奖励/报告/流水。discoveryLog为空；初始selection由配置给出；enabled=false/IDLE，preferred=freeBait；nextAttemptSeq=nextObjectSeq=ads.nextSeq=1，各终止水位和lastClientCommandSeq=0，stateRevision=0，cursorMs=初始时间，lastWallMs=highWaterMs=初始时间。初始化每个已发布地区的独立世界环境（包括未解锁，不公开其隐藏状态）；ads.speedUntil=0,nextOfflineExtensionMs=0,quotaDay=当前业务日,usedByDay={},speedMultiplier=1；其他计数0。默认Policies：retain=[]、sell=[]、overflow=STOP、replenish.disabled（batch=1,reserve=0,onInsufficient=STOP）。默认不强卖鱼、不自动补货、不自动开始；该默认策略属安全工程建议，后续新手体验可由配置或产品另行确认。必须先提交初始存档，再允许任何业务操作。

## 2. 状态转换表

| 当前 | 事件及前置 | 下一状态 | 原子变化 |
|---|---|---|---|
| IDLE | START合法且permit | CASTING | tryStart创建尝试、扣饵/补货 |
| CASTING | 工作完成且达到最低时间 | WAITING | 一次wait需求抽样；清空阶段工作 |
| WAITING | 当刻有效候选、需求完成、minReal达到 | FIGHTING | 替代分支或鱼种/个体/对抗计划锁定；work归零 |
| WAITING | 空池/硬超时且未满足有效咬钩 | SETTLING | outcome EMPTY，零鱼、零鱼XP |
| FIGHTING | 首失败节点 | SETTLING | outcome FAILURE/failure及精确work；未到节点不执行 |
| FIGHTING | 全部节点完成且最低现实时间达到 | SETTLING | SUCCESS（真实鱼）或REPLACEMENT（替代物） |
| SETTLING | 结算完成 | PREPARING或PAUSED | 清除已终止attempt，建立准备工作，若待处理立即暂停并保留准备 |
| PREPARING | 工作完成 | IDLE | 清除prepare；若enabled及permit尝试启动 |
| 任意有效阶段 | 离线截止/必须暂停 | PAUSED | 保留pausedFrom、work、attempt/prepare；世界继续 |
| PAUSED | 原因解除及合法恢复 | pausedFrom或IDLE | 同一尝试不扣饵、不重抽；无尝试才可能新启动 |
| 未完成阶段 | 合法STOP/换配置 | IDLE或新CASTING | 旧尝试CANCELLED，标终止，已消耗不退；结算后的PREPARING可清理不撤销奖励 |

SETTLING是逻辑零时间，不得提交只有半份结算的中间状态；若故障在进入和完成间，恢复到先前一致的待执行节点。PREPARING采用上一尝试快照、结果对应准备耗时；阶段终止后释放旧版本引用（若仍有历史定价需求另保留）。主动取消后无失败XP、失败成就、保底；计入cancelled及已扣饵统计。

## 3. EngineApi.advanceUntil 事件推进

入参：不可变state、target安全整数毫秒且>=cursor、context(mode,deadline,versions,maxNodes>0,allowStartAtTarget)。OFFLINE模式必须存在原会话且deadline相同；WORLD_ONLY仅推进环境、现实权益到期、逻辑cursor，不推进捕鱼、不抽个人随机。`maxNodes`是一次执行切片预算，不是玩法超时；达到预算返回reachedTarget=false及安全候选state，下次接续。遇到mustCommit=true的完整同刻事件组即返回当前安全状态（即使未达到预算或target），应用先提交再继续。每个同刻完整事件组不可被预算截断（可超本次maxNodes处理该组），组内连锁有独立maxEventSteps硬保护。应用层按实际设备分片，让出事件循环；切片之间只允许内部继续、生命周期通知排队，不允许玩家改变离线结果。

伪代码（关键）：

```text
while cursor <= target:
  build next event times from current stage, relevant environment versions,
      ad expiry, offline deadline, target
  t = min(all timestamps >= cursor)
  integrate stage progress on [cursor,t) using old rates (unless WORLD_ONLY/paused)
  accumulate real elapsed fishing/paused/lost stats and attempt.activeElapsedMs as appropriate
  cursor=t
  handle environment expiry and transitions (all due, sorted)
  handle ad expiry / business day / scheduled config switch boundary
  handle due stage events and fight nodes (failure before success)
  settle terminal attempt once; apply chained rewards, establish prepare
  if t == offline deadline: freeze before replenishment or new cast
  if caller reserved a player command at t: do not start new attempt yet
  else if permit and enabled and no blockers and (t < target or allowStartAtTarget):
      if preparation finished or idle: tryStart
  if t == target and no unresolved same-time work: return reachedTarget=true
  if safe-group node budget reached: return reachedTarget=false
  if no time advance and no state transition/consumed event: INVARIANT_VIOLATION
```

细则：环境或广告边界t前的速率不得应用于[t,...); 抛竿/等待的整数工作到t后夹紧，不将多余工作传给后续阶段。若同刻候选消失而等待已达阈值，先更新环境再判断有效咬钩；到超时无合法鱼则空竿。若新速率变化无节点到达，不重新抽样。战斗计划节点按work位置、类型优先级及id执行；现实同一ms跨不同节点时按work的真实顺序，不因切片变更。`settleAttempt`完成后如prepare工作量合法为正，则不会同刻立即消耗下一饵。若有零耗时结算/事件奖励，只能有限次执行，不允许0时长抛竿循环。OFFLINE截止时已达成功/失败节点照常处理，禁止启动或补货；超过截止的部分由WORLD_ONLY推进世界并记录lostMs，不再推进钓鱼。对同刻用户命令：先结算已经发生的节点，再命令，再一次tryStart；命令拒绝仍可在合法情况下继续原任务。在线tick的末端允许启动；命令预推进末端禁止启动。不得因maxNodes或UI帧率重新随机或重置工作余数。

## 4. tryStart 的精确流程

输入 state、versions、permit。若!permit、!enabled、非IDLE或有正在进行attempt/prepare，则不变；PAUSED除显式恢复流程外不进入。检查pending→STOP且仓库数量>=cap→地区/位置/装备准入→结构性饵适配。上述正常阻断设置PAUSED与具体原因，不消费金币、不生成AttemptId；隐藏非法引用/配置错误返回错误不变。SMART/SELL_NEW在满仓时允许继续（可能直接售新鱼或待处理），不得在抛竿前先卖旧鱼来赌未来捕获。临时天气空池仍可开始并按等待超时。

CONSUMABLE：库存>=1直接使用，不自动补足批次。库存=0且enabled补货：按17可购买资格、当前生效的唯一offer、16.replenishQuote求quantity；可部分购买。quantity>0时增加库存、扣金币、记流水及报告；如0/商品不可买按onInsufficient回退FREE或暂停。即使补货开关关闭，库存0也应用预设FREE/STOP。FREE回退必须校验基础饵在当前位置的结构适配/使用条件，若不适配暂停NO_BAIT，不换位置。只更新effective selection.baitId，保留preferred；重复后续使用FREE，不自动回原。REUSABLE/基础FREE不扣库存、不发补货广告、不扣参考价。校验所有运行许可之后才消费；补货+创建attempt+扣1份库存同一候选事务，不留下已扣款未启动的中间档。

生成 `attempt.seq=nextAttemptSeq`, `id=epoch:attempt:seq`，nextAttemptSeq+1；castSnapshot包含有效配置版本、选择、有效属性、等级、requiredLineM、消耗饵参考价（FREE/REUSABLE为0）、当前cursor。baitDebitKey=`['bait',attempt.id]`；仅消费型扣1，累加baitUsed、当前会话consumedBaitReferenceGold及各维度；开始次数在成功创建attempt时增加（离线报告attempts按本会话启动计，跨界完成可使success>本会话启动数，另记完成数供解释）。计算castWork并建立work状态、phase=CASTING，stage进度=0，activeElapsedMs=0。`lastTerminalAttemptSeq`不增加直到终止；一份存档只允许一个尝试，下一尝试前旧seq已终止。历史统计的成功率按实际终止SUCCESS/FAILURE，不用启动次数替代。随机数在开始阶段无需抽样，等待开始才抽。

## 5. WAITING 到 FIGHTING

读取cast锁定版本、当前环境和当前合法状态，调用distribution；无有效鱼池/活动0不调用随机。存在候选：先评估符合条件的REPLACEMENT事件（第9节）；每个咬钩节点至多一次替代抽样。若选中替代事件：保存eventId，FIGHTING作为回收阶段，work.required=配置recoveryMs×1e6（必须正且在fight合法工作范围内），不生成fish/fight，不调用正常鱼随机，回收完成后REPLACEMENT；回收中可取消且不发奖励、不消费额外饵。若无替代：从鱼种流抽1个U选择candidate，个体流抽3个U生成鱼（fishId=`epoch:fish:attempt.seq`，不单独递增对象序号），捕获流固定5个U生成plan；保存鱼、plan、work.required=plan.totalWork、done=0。特殊遭遇仅判定现有鱼的合法ENCOUNTER规则，保存encounterKey为稳定第一个匹配ID的presentationKey；不再抽鱼，不显示确切重量/体色。计划节点work=0的必经检查在同刻执行，失败立即结算；禁止先推进到未来才执行初始检查。咬钩和对抗配置版本不因换页、退出而变化。

## 6. settleAttempt 的原子处理

入参 attemptId必须等于当前attempt.id且已合法到达终止节点，非CANCELLED路径由引擎内部产生；UI不可构造捕获结果。重复调用已终止seq≤lastTerminalAttemptSeq返回STALE_COMMAND（无任何变更）；未知id或非当前NOT_FOUND；非法phase/结果INVARIANT_VIOLATION。函数返回候选state、AttemptSettlement和mustCommit。

执行顺序：

1. 快照结算前收藏/纪录、当前金币及历史首次标志。SUCCESS构造CatchArchive（鱼ID、捕获前后环境、原cast、flags、rarityAtCatch），FishInstance临时对象尚未入库。flags.firstSpecies全局无捕获；firstRegion为region×species无捕获；firstColor该鱼种特殊色未记录；newRecord=任一已批准最大或最小纪录新建/刷新（普通首次也可满足保护规则）。FAILURE/EMPTY/REPLACEMENT无正式fish；失败原因和节点由已锁定计划得出，禁止抽总成功概率。
2. 更新成功档案、全局/地区鱼种统计、纪录和实际历史；每次成功捕获数量+1、weightG求和、首次时间不改，集合去重；失败统计按具体原因一次，EMPTY只空竿，REPLACEMENT单列。档案中重量/体色/捕获快照不可更改。按鱼饵、竿线、位置、天气等维度稳定键聚合。失败不写成功鱼种/重量档案。
3. 事件：替代事件发已选奖励；其他按有效结果和条件评估EXTRA/DISCOVERY；更新合法保底；重要发现/特殊竿去重及重复转换。事件奖先更新工作副本，XP作为待处理奖励进入队列，不能独立提交。全局首次及纪录XP使用第1步快照，调用xpSettlement，更新一次性键及基准；不得因第2步已更新历史而漏奖励。
4. SUCCESS依据最新策略与flags决定鱼获归属，见第7节。自动售鱼按出售当刻生效版本（而非旧cast价格版本），GoldEntry记新鱼/旧鱼及原因；档案不丢。若pending创建，后续必须停止新尝试。无鱼不调用仓库流程。
5. 统一处理捕获/事件XP、升级、成就、奖励连锁及资格，见第10节。若额外发放鱼饵或金币影响下一轮，必须在下一轮tryStart前全部完成。达到免费/付费地区资格不自动扣钱；发现奖励明确指定解锁则自动加入unlockedRegions/discoveredPositions。
6. 更新结算水位、attempt.settled=true（候选中间字段），记录AttemptSettlement及GoldEntry、实际耗饵/捕获/时间（activeElapsedMs，不含暂停）、报告；必须将本次终止seq标入lastTerminalAttemptSeq。当前Attempt移除，创建prepare（上一cast、outcome/failure、work）；若pending存在则phase=PAUSED,pausedFrom=PREPARING,pauseReason=PENDING_FISH。否则PREPARING；满仓STOP可完成准备后停在下一次启动检查。原enabled不变。
7. 全量校验I01—12；失败则返回错误，原输入不可变。mustCommit=true条件：首次鱼种/地区/体色、特殊色、任何重要纪录/纪录里程碑、任何一次性奖励、发现、成就、特殊竿、pending，或应用正在离线检查点/玩家指令。普通结算可仅内存原子提交，按19批量持久化。失败和取消不计成功保护。取消通过CMD路径终止水位、清理当前尝试，不进入准备或随机事件。

## 7. 鱼获归属决策矩阵

先判断新鱼 retain 匹配（flags冻结、规则取当前），再判断 sell；如retain=true，sell忽略；若retain=false且sell匹配，无论仓库是否满，直接AUTO_SALE新鱼。否则需要保留。若仓库有空位，直接WAREHOUSE。仓库已满则：

| overflow | 新鱼受保护 | 可卖旧鱼存在 | 结果 |
|---|---|---|---|
| STOP | 任意 | 任意 | 新鱼PENDING，暂停（一般由作钓期间其他合法操作填满导致） |
| SELL_NEW | 否 | 任意 | AUTO_SALE新鱼 |
| SELL_NEW | 是 | 任意 | PENDING，暂停；不卖旧鱼 |
| SMART_SELL | 任意 | 是 | 选最便宜旧未保护鱼出售，再新鱼WAREHOUSE |
| SMART_SELL | 否 | 否 | AUTO_SALE新鱼 |
| SMART_SELL | 是 | 否 | PENDING，暂停 |

SMART候选仅WAREHOUSE；manualLocked或当前retain匹配者排除；报价BigInt升序、catchAt升序、ID升序，取1条，不按对象原顺序。已在鱼缸/PENDING不可自动卖。新鱼可能被迫进入待处理即使未匹配retain（STOP政策），不能丢弃。生成第二条pending为INVARIANT_VIOLATION。PENDING正常拥有及历史已结算；后续MOVE/SELL仅变更归属或金币，不再发捕获奖励。主动卖保护鱼需17明确确认。自动出售旧鱼计入真实现金/统计，但不计本次离线广告的“新捕获鱼自动出售”收入（如旧鱼是在同一会话捕获后保留再被智能清理，按E10见第11节）。

## 8. 收藏/纪录接口内部规范

纪录scopeKey固定 JSON数组键：`['global']`、`['species',speciesId]`、`['color',speciesId,colorId]`、`['region',regionId]`、`['regionSpecies',regionId,speciesId]`。每scope初次建立max=min=w、maxFishId=minFishId=当前鱼，maxTies=minTies=1，写两条MIN/MAX历史；已有记录：w>max更新max/maxFishId并重置maxTies=1，w==max只+1；w<min对应MIN，等于min只+1；不得将并列鱼替换首次纪录档案。普通纪录XP基准及里程碑只写species scope；其他scope只历史和成就。全局纪录只记录实际成功重量。统计按捕获时鱼种、环境、版本，出售或新版本不修改历史。首次颜色flags仅特殊色，首次普通色仍进入图鉴colors集合。平均重量计算总克数/数量，不累计浮点平均值。重要档案包括首次鱼种/地区/特殊色及所有实际纪录历史引用，另保留重要遭遇/发现关联档案；普通已售且无引用才可裁剪。统计键按15编码，禁止把失败鱼种公开为已发现。

## 9. 环境、意外和探索事件

### 9.1 世界环境推进

世界时间 `anchorGameMs+(realMs-anchorRealMs)*12`，锚点跨版本保持不变；日期按游戏分钟映射日相[start,end)。边界转真实毫秒采用向上取整，保证不提前发生。每region及有效configVersion独立环境状态；初始化weather根据initial权重抽1次，持续时长从[min,max]游戏毫秒均匀抽1次（整数区间）；到期先按transition[oldWeather]抽下一个状态及持续期（允许同天气重选），nextWeatherAt必须>当前真实ms。每环境事件初始nextCheck=初始化时刻+ceil(checkEveryGameMs/12)；同刻处理顺序：移除到期active事件→天气变化→检查环境事件（regionId,eventId升序）→计算日相及当前modifier投影。一个stackGroup最多1个active，已有则本次不抽，nextCheck仍按原计划推进；否则评估仅世界、时间、天气作用域条件，满足时抽1个U，触发则加入active并设endAt；检查时刻按固定周期推进，不以帧更新时间作为起点。环境事件无个人幸运或个人保底；暂停仍推进世界，个人事件不发生。禁止未解锁地区将环境奖励发给玩家。温度等未配置因素不模拟。inactive地区的环境也需推进，长离线允许切片；不得无限循环。

### 9.2 条件执行器

`evaluate(condition, context)` 为纯读取。ALL空集合=true；ANY空=false；NOT取反。LEVEL在捕获/等待事件使用cast.level，商店/地区/成就用当前level。CURRENT_*、DAY_PHASE、WEATHER在抛竿/咬钩或结算节点读取对应快照；环境事件只允许CURRENT_REGION/DAY_PHASE/WEATHER组合；FISH_*只允许成功结算或ENCOUNTER（已生成plannedFish），OUTCOME只在结果节点；读取不存在的上下文字段是配置错误而非默认真。STAT取指定聚合计数，SPECIES_COUNT按已成功物种去重，RECORD为scope最大重量，ELIGIBLE_ATTEMPTS读取对应pity计数。查询条件不抽随机、不发奖。配置验证拒绝错节点条件；成就中的当前鱼/位置条件只能与捕获事件共同求值，不得由登录时凭空补发需要具体现场的成就。

### 9.3 个人事件及软保底

REPLACEMENT候选仅在有效咬钩节点，按eventId排序，条件与一次性claimKey检查；`p_i=clamp(baseChance*luckMultiplier*pityMultiplier,0,1)`，总和若超过replacementCap则同比缩放，抽1个U按[累计概率]区间决定一个事件或NONE；无候选不抽。事件奖励要在回收成功结算才发；取消不消耗一次性claim、不增加有效保底，已消耗随机状态不倒退。EXTRA/DISCOVERY在合法结算节点：先筛eligible、未领取一次性、符合触发时机；候选按ID，单项p同上，和超extraCap同比缩放；对每个候选独立抽1U，可多个命中；全部资格按结算前统一事实快照判定，不能因前一个中奖即时改变其他候选的抽样。普通有效尝试为SUCCESS、REPLACEMENT或物理可行且真实失败的FAILURE，取消/空竿/物理不可行失败不触发个人额外奖励/保底；默认探索保底仅SUCCESS且满足pity.eligible，可在配置白名单内允许物理可行有效失败或REPLACEMENT。保底倍率 `min(maxMultiplier,lerp(curve,currentCount))`，先判本次，再对符合条件未命中者+1；命中目标并成功发放后按一次性目标关闭/归零。保底不作用于鱼种、重量、体色和纪录；已取得一次性目标不再累计。独立空池个人事件本版无配置类型，不实现；需新增事件节点时另行评审。重要发现日志记发生时间、来源、关联尝试/档案（如有），永久保留。重复特殊竿转为配置奖励，禁止递归重复转换环。

## 10. 连锁奖励队列

每次业务事务建立FIFO队列；同一步多条事件按稳定id排序。事件包含类型、来源operationId、时间、关联捕获事实及状态变化。建议固定 `FISH_CAUGHT, RECORD_CHANGED, DISCOVERY_UNLOCKED, XP_GRANTED, LEVEL_UP, GOLD_CHANGED, ACHIEVEMENT_COMPLETED, INVENTORY_CHANGED`；每个处理器只追加事件，不直接递归调用另一个处理器。XP发放调用grantXp，按升到的每个等级升序产生LEVEL_UP；钱包改动同时写流水与统计。成就在初始事件及后续每个可改变条件的事件后按stageGroup/stageOrder/id评估；一次性键在发奖励前写入候选状态，条件满足且未领才追加奖励；捕获上下文使用当前事务中的真实捕获事实，不能在非捕获事务冒用上一条鱼。配置阶段顺序不得强行跳过前置成就，若同事务满足多个阶段可依序完成。RewardDef.items按数组顺序发放，GOLD/XP非负，BAIT库存到上限时溢出部分记录为未领取数量并发notice（E项补充建议：常规奖励保留已有库存，不为超额自动换金；发布配置需验证合理上限）；永久装备重复若有duplicateRewardId按对应奖励转换，否则无变化；发现重复不重复发解锁，COSMETIC仅已有配置且不重复。任何事件步骤超过maxEventSteps、重复转换环或不变量违反整笔事务失败；不允许截断后部分入账。一次性键 `['achievement',id]`、`['discovery',id]`、`['event',claimKey]`、`['firstSpecies',id]`等按实际永久目标持久化，不附配置版本；普通事件无一次性键，但受attempt唯一终止水位约束。所有奖励写入同一个候选state；没有单独“领取”成就接口。

## 11. 离线会话报告与时间归属

onHide在推进当刻已到节点后、禁止新抛竿的边界创建会话；锁定永久额度及一次性nextOfflineExtension（min24h），同时消费临时扩展为0；startedAt=cursor，deadline=startedAt+allowance；settledUntil=startedAt，target暂缺，acc全零。会话创建必须持久化；如果当时钓鱼已IDLE/PAUSED，仍可记录离线会话，但不产生钓鱼收益；不强制开始。onShow锁定target=min(有效恢复墙钟,deadline)并先持久化，不因重启改变target；有效离线区间按OFFLINE模式推进。截止暂停当前阶段，再WORLD_ONLY推进到恢复墙钟；未到截止的正常回到在线可保留阶段继续。离线升级不改变原deadline。补算执行期间实际经过时间按E12不追加钓鱼收益；补算完成时再以WORLD_ONLY推进到当刻、生成最终报告并持久化，清除offline、恢复RUNNING，才允许新正常退出创建新会话；若期间收到HIDE排队，完成后按最新真实生命周期处理，不凭空领取新额度。

报告统计：fishingMs为CASTING/WAITING/FIGHTING/PREPARING实际有效时间（含空池等待），pausedMs为额度内停钓/暂停时间，lostMs为额度外实际离线时间，不重复计算。每次抛竿消耗参考价值按消耗发生时间归属会话；一次尝试跨会话，起点前消耗不追溯扣本报告；成功鱼捕获时间在会话有效范围内且当次自动出售，计newFishAutoSaleGold；智能出售此前保留的鱼即使该会话捕获也不属于当次新鱼即时自动出售，不计eligible（E10明确口径）；手动售、事件/成就/广告金币均不计eligible，但计真实现金。跨会话开始的鱼在本会话捕获并当次自动出售则收入计本会话；抛竿发生在上一时段则成本已归上一时段，接受该边界差异，不重复摊派。所有同刻deadline已完成结算仍归原会话，截止后不新抛竿。报告保留实际金币及鱼价值、捕获成功/失败/空竿/替代、经验升级、饵使用/购入、高亮档案及发现/成就；reportId=`epoch:report:sessionObjectSeq`。生成时锁定当前适用报告规则版本、eligible/reward、claimExpiresAt=完成时间+配置窗口；0奖励不提供广告；报告只用于展示和广告附加奖励，基础收益早已结算，关闭报告不再发奖。未完成report生成及清除offline同一存档；恢复时若已生成不得再生成第二份。
