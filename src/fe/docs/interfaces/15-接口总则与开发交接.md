## 2. 工程职责、依赖及命名

`contracts` 不依赖平台；`game-config` 负责数据验证和版本解析；`game-core` 负责纯规则及业务状态变换；`game-application` 负责队列、时钟、生命周期、存档协调与只读投影；`game-client` 只负责渲染及微信适配；`simulator` 使用 application/core，策略只能发命令，固定/压力初始化必须明确标记。禁止在 UI 或模拟器重复计算规则，禁止核心调用 Date.now、Math.random、wx、cc、fs。Cocos 仅保留必要启动场景，代码创建业务页面；UI视觉另行设计。

建议目录：`packages/contracts/src/index.ts` 由随附 contracts.ts 拆分后统一导出；`packages/game-core/src/{models,environment,events,fishing,inventory,collections,rewards}`；`packages/game-application/src/{commands,queries,queue,lifecycle,persistence}`；`packages/game-config/src/{schemas,validator,versions}`；`apps/game-client/assets/scripts/platform/wechat`；`apps/simulator/src`。同一核心源码经构建分别运行，禁止手工复制。确定工具链版本、BigInt 和 Math 函数跨运行时一致性为 S0 门禁，不通过不得默默降级。

## 3. 数据约定

- `Id`：内容ID使用 `[a-zA-Z0-9_.-]+`，全局同集合唯一，永久不复用；禁止 `__proto__`、`constructor`、`prototype`；名称不作为ID。运行ID由 `saveEpoch`、类型、单调序号组成，例如 `epoch:attempt:42`。组合键使用 JSON.stringify 字符串数组，不允许用可能冲突的分隔符拼接。字典仅遍历自有键；所有稳定排序用 UTF-16 code unit 比较（`a<b`），不用 localeCompare。
- `Nat`：十进制非负整数字符串（无符号、无前导零）；`Signed` 可有负号但不允许 -0。运算使用 BigInt（序列化前转换为字符串），禁止 JS number 金币/XP 直接累加。`Ms` 非负安全整数毫秒，墙钟 UTC epoch，duration 独立；所有相加必须检查 Number.isSafeInteger。重量整数克，米和牛顿有限数值。比例[0,1]，倍率非负，物理参数必要时严格正。JSON不允许undefined数组元素、NaN、Infinity；可选字段缺失表示未设置，不使用 null 代替。零不是缺省。类型校验还需运行时 Schema，TS 不提供安全验证。
- 正常业务整数四舍五入 `floor(x+0.5)`，失败XP向下、升级XP向上，售价最低配置值（推荐1）；成功基础XP最低1；内部计算不按展示单位取整。对正 Nat 乘浮点倍率：先将最终倍率四舍五入为百万分数整数 `q=round(m*1e6)`，再用 BigInt 算 `(v*q+500000)/1000000`（floor/ceil 使用对应公式）。连续公式的输入比值只在数值模型内转换为 number；无穷、非有限或不可表示返回 NUMERIC_LIMIT，不静默截断。升级经验幂公式需检查 finite，计算后转 BigInt(ceil(...))；超大等级进入明确技术限值错误，不作为玩法封顶。S0必须验证兼容性；大数进一步数值算法由设计负责人定，不让开发者擅自更换。记录和判定使用原始数据，不使用显示值。
- 所有输入、返回、存档以独立不可变快照或深拷贝实现；不得返回可修改内部引用。纯函数失败时原输入深等不变。禁止核心内部读取 UI 状态。
- `stateRevision` 为逻辑业务版本；每个成功的逻辑事务或时间事件批次递增一次；不因一次读查询改变。持久化 envelope.revision 为物理提交版本，独立递增；SaveRepository 的 expectedRevision 只使用 envelope.revision。逻辑版本和物理版本不得混用。分片一致性比较业务字段排除 stateRevision/命令回执/物理提交元数据；不排除 RNG、时间游标、鱼获与余额。一次命令先推进到输入时间后再执行；具体版本检查见17。

## 4. 公共结果和错误约定

所有 `Result` 接口成功 `{ok:true,data}`，失败 `{ok:false,error:{code,field?,detail?,retryable}}`，不得以 null 表示业务失败。`detail` 是诊断键或简短文本，不直接作为UI文案，不泄漏未发现内容。无 Result 的纯函数仅在已校验输入上使用；违反前置条件抛内部 typed fault，由 application 转为 CONFIG_INVALID/NUMERIC_LIMIT/INVARIANT_VIOLATION；不得返回任意0继续结算。异步平台错误统一转换。调用方按 code 处理，不按中文文本判断。下列分类适用所有接口：

| 类别 | 错误码 | 行为 |
|---|---|---|
| 参数/权限 | INVALID_ARGUMENT, NOT_FOUND, LOCKED, NOT_OWNED, ALREADY_OWNED, NO_CHANGE, UNSUPPORTED_FEATURE | 不重试；修改输入 |
| 资产/准入 | INSUFFICIENT_GOLD, INSUFFICIENT_POINTS, INVALID_SELECTION, LINE_TOO_SHORT, CAST_TOO_FAR, DEPTH_TOO_DEEP, NO_BAIT, STOCK_LIMIT, WAREHOUSE_FULL, FISH_PROTECTED, PENDING_FISH, TANK_INCOMPATIBLE, TANK_FULL, NO_TANK_SLOT, NOT_NEXT_TIER | 不自动修正用户选择；显示原因 |
| 指令 | NOT_RUNNING, BUSY, STALE_REVISION, STALE_COMMAND, COMMAND_CONFLICT | BUSY可稍后重试；STALE_REVISION重新读，重新发新序号；旧序号不重放 |
| 广告 | AD_UNAVAILABLE, AD_LIMIT, AD_EXPIRED, AD_IN_PROGRESS, ALREADY_CLAIMED | 不扣玩家资产；同一个请求按19处理 |
| 技术故障 | CLOCK_ERROR, CONFIG_INVALID, VERSION_UNSUPPORTED, SAVE_CORRUPT, SAVE_IO, SAVE_UNCERTAIN, MIGRATION_FAILED, NUMERIC_LIMIT, EVENT_LIMIT, INVARIANT_VIOLATION | 阻断相应事务；保存旧档；仅可恢复类允许重试 |
| 确认 | CONFIRM_REQUIRED | 明确二次确认后重新发命令 |

## 5. 全局不变量（任何业务事务提交前校验）

I01 金币、库存、XP、已/未分配点均非负；金币余额=上一个余额+流水净变化；等级>=1且当前XP小于当前升级需求；初始/每级发点规则版本变化不得追溯增减已获得点数。I02 鱼权威归属唯一，库存数量不超仓库上限，鱼缸不超单体及总空间，待处理最多1条；已售鱼不在持有集合，历史仍在。I03 一次尝试仅扣一次饵/结算一次；activeAttempt 与阶段一致；终止序号小于 nextAttemptSeq。I04 每个一次性奖励键唯一，重复装备不能复制，免费及广告不增加 paidResets。I05 时间游标单调，环境边界和阶段进度合法，离线截止不超过24h，截止后无新抛竿。I06 RNG流状态完整，已锁定鱼、风险节点、配置版本可恢复。I07 保护鱼不被自动出售；对抗硬上限不能被属性或广告突破。I08 失败/取消不创建成功鱼或图鉴；取消无XP/保底；未完成对抗对UI不公开重量/体色/潜在结果。I09 版本引用可解，未结算尝试使用锁定规则，已完成交易不追溯。I10 所有写入口串行；存档提交结果不确定时禁止继续写，先恢复。I11 P0无强制广告、无IAP、无云端必需依赖。I12 没有缺参时偷偷套用默认正式数值。

## 6. 未决细节的推荐实现（需要本轮评审；确认后开发AI不再选择）

| 决策 | 对应v0.2 | 推荐实现 |
|---|---|---|
| E01 | D01/D12 | 整数毫秒及微工作单位，BigInt累加；速率与工作阈值只在自然事件变更时量化，见16/18；最低现实时间限制完成节点，失败允许提前；等待硬超时与累计空池超时均按有效现实时间计 |
| E02 | D02/D06 | 同刻持续/爆发客观负载→操作负载→力量→脱钩→完成；竿线同限鱼线优先；同类稳定ID；无额外对抗也经过必经节点 |
| E03 | D03/D04/D05 | 候选先排空重量池；普通色必须始终正权重；离散重量逆CDF，有限随机分辨率校验；活跃按基础种群权重平均，非零适配只做布尔过滤，不用幸运加权 |
| E04 | D07 | 捕获时首次/纪录标签永久保存；自动保护按当前规则重算（含这些历史标签），手动锁永久；更改规则不立即出售旧鱼；SMART满仓时可卖最便宜旧未保护鱼，不比较新鱼价格；无旧候选且新鱼未保护则卖新鱼；新鱼保护则待处理 |
| E05 | D08 | 常规最大纪录XP门槛=max(绝对克数, ceil(上次奖励重量×相对比例))，首捕建立基准，未跨阈不更新奖励基准；每捕获至多发一次普通纪录XP，跨多个重量里程碑分别发 |
| E06 | D10 | 库存为0触发自动补货；数量受容量限制；免费饵无适配结构候选则暂停NO_BAIT，不自动换位置；暂时因天气空池不判鱼饵非法 |
| E07 | D11 | 替代事件回收耗时作为特殊 FIGHTING 分支；普通个人事件在有效结果节点处理；无配置独立空池事件则不触发；保底条件和有效尝试见18 |
| E08 | D09 | 新版本加载前按旧配置补算至锁定恢复目标；旧尝试持有旧配置及环境投影直至终止；保留所有仍可升级的历史版本包，缺失直接 VERSION_UNSUPPORTED；不丢弃旧档或静默重算 |
| E09 | D12 | PRNG xoshiro128** v1 每个逻辑抽样固定两次原始输出形成U53；分流规则见19；配置/工具链跨运行时黄金向量验证 |
| E10 | D13 | 广告业务日固定 UTC+8（可配置但同一发行版稳定）；高级鱼饵使用共享每日一次组；成功计入请求发起日；播放只允许单请求；报告金按实际抛竿扣饵、自动售鱼发生时间归属会话，不把跨会话旧鱼当新鱼；详见19 |
| E11 | D14 | 尝试终止序号水位+当前尝试、广告终止序号+当前请求、单次命令最新回执用于去重；一次性奖励键永久；普通流水/明细分批裁剪但保留总计；删除标记防备份复活；裁剪阈值配置见19 |
| E12 | D13 | 补算恢复目标在开始时持久化，补算过程实际经过的时间只推进世界，不产生额外收益；完成后才开放命令/新会话；广告播放期间照常推进，平台生命周期真实进入后台仍按会话规则处理 |
| E13 | D15/D16 | 真实数值、生态、广告收益及性能验收阈值保留待模拟/真机，不冻结；测试配置与正式配置隔离 |

其他需一并确认的实现细节：重置增长倍率使用安全整数>=2（默认试验2）；初始自动售/保留均关闭、满仓停止、自动补货关闭、手动开始；鱼缸升级全价；普通鱼饵奖励溢出不换金币；广告预留库存；新版本剩余XP按新需求规范化；前台墙钟容差和删除确认窗口可配置。详见16—19。

以上 E 项是设计者明确给出的实现选择，而非声称用户已经批准。E08 的兼容策略可能增加包体；BigInt/Cocos兼容及跨JS Math一致性必须验证。若无法通过，只阻塞依赖任务，不能擅自改模型。

## 7. 工作方式与交付

先读文档00、05、09—14及本套；先执行SPIKE-001，不实现完整业务。S1/S2每次只实现20号规定的一组接口。新增代码必须有正反向和边界测试，缺配置/平台能力时标记 BLOCKED；不得用假数据冒充真实接口。修改前列文件、目标接口、验收ID；修改后给出命令、退出码、测试日志、失败及阻塞证据。未经产品批准不得添加新玩法或修订E项。没有需要开发者自行设计的分支时直接按文档实现；遇到规格冲突、实际平台不支持、未提供的正式数值，报告并停止相关路径，不让低能力AI作产品决策。
