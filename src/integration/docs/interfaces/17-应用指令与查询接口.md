# 17｜应用指令与查询接口详细设计

依赖15、16、18、19及contracts.ts。所有写操作仅通过 ApplicationApi；不得由页面直接调用内部 settlement 或替换 GameState。各命令按本文件执行，输入未明确的字段不接受。所有命令不允许在OFFLINE_SETTLING、MIGRATING、RECOVERING、ERROR或BACKGROUND期间执行；只允许生命周期、内部广告回调及专用恢复/删除路径。所有玩家资产操作为完整逻辑事务。

## 1. 命令通用协议

`dispatch({seq,expectedRevision,command}) -> Promise<Result<CommandReply>>`。调用方从读接口取得最新逻辑revision；seq为同一存档世代严格递增的客户端指令序号（下一序号=最后已处理+1，首条1）。应用实例通过read.commandMetadata()分配下一序号，页面不得自行猜测或并行使用同一序号。请求规范JSON SHA256为requestHash，包含seq、expectedRevision和command。旧seq<last返回STALE_COMMAND；等于last且hash相同返回已保存原回执（不推进时间、不重放）；hash不同返回COMMAND_CONFLICT；跳号INVALID_ARGUMENT。新命令先检查输入revision是否等于进入队列时当前业务revision，若不等则STALE_REVISION；该失败不消费seq。校验通过后读取时钟、推进旧状态到命令生效时间，处理同刻已到节点但不自动开启新尝试；再以推进后状态执行业务校验。正常业务拒绝保留已合法推进的状态，命令自身无资产变化，记录拒绝回执并消费seq。参数错误或锁定运行状态等发生在入队前的拒绝不消费seq。失败回执需要持久化的条件与成功一致（推荐所有玩家写指令立即提交），不能将失败后序号与状态分别写入。

成功返回 `changed=true`、最终revision、该命令直接导致的净金币变化（不含之前推进收益）、直接新增/移除/移动的fishIds、创建或变化对象objectIds、notice keys、可选adRequestId。已是目标配置或无效果操作返回NO_CHANGE，不扣费。错误字段指向输入路径；所有批量输入全量验证后统一变更，禁止部分出售。事务提交后再向调用者确认，触发订阅；失败回执不得包含旧状态可修改引用。若不确定持久化是否成功，进入恢复态，按19确认后才返回已提交回执，不得重发资产操作。应用错误发生时不能继续启动下一轮。

公共校验顺序：运行状态→命令结构与参数→序号/版本→推进至当刻→对象存在→权限/资格→资源→冲突与容量→构造候选状态→连锁事件→不变量→持久化→响应。每项业务具体顺序见下文。`EngineApi.applyCommand`只负责业务变换，无IO；调度、seq及commit由应用层负责。非幂等命令必须经过序号协议。UI可先查预览，不可将预览作为最终授权。

## 2. 作钓命令（CMD01—07）

### CMD01 START_FISHING

入参仅type。前置：IDLE且未启用，或已有暂停由RESUME处理；非IDLE返回NO_CHANGE/BUSY。校验当前selection、pending、仓库STOP及结构候选。合法设置enabled=true，交给同刻最后启动检查（18）。饵不足可按现有策略自动补货/免费回退；若最终不足，保存PAUSED/NO_BAIT及enabled=true并返回相应notice，不创建AttemptId，不扣饵。只有真正抛竿才创建尝试。无足够空间且STOP时暂停，不自动出售旧鱼。成功回执给出当前尝试ID（若有）。

### CMD02 STOP_FISHING

正在CASTING/WAITING/FIGHTING时取消当前尝试：写终止序号及CANCELLED统计/必要流水，不退款，不给XP、鱼、图鉴、有效保底或失败成就；已有SETTLING先按同刻规则完成不可撤销结算，不能抹去鱼。PREPARING仅清除准备工作（已结算不撤销）；PAUSED有未完成尝试时同样取消；pending鱼仍保留，不能通过STOP清除。enabled=false，IDLE（pending仍阻止新尝试）。重复停止返回NO_CHANGE。

### CMD03 RESUME_FISHING

仅PAUSED；先检查暂停原因已解除、无pending、当前阶段所需引用可解析。因OFFLINE_LIMIT且已上线可恢复；因时钟或存储故障只能由恢复流程解除，不接受玩家强行恢复。若pausedFrom为CASTING/WAITING/FIGHTING，恢复原AttemptId、工作及随机结果；若为PREPARING恢复准备；若无尝试/准备，按新启动流程。不得重新扣饵。若不满足保留暂停状态，返回具体原因。在线正常离线恢复时可由应用内部自动执行同一规则，其他暂停由用户操作解除。

### CMD04 CHANGE_SELECTION / CMD05 CHANGE_REGION

入参完整Selection；CHANGE_REGION.regionId必须等于selection.regionId；只允许已解锁地区，客户端可以通过 lastSelectionByRegion 提供候选，但服务端式逻辑不自动选择非法默认位置。校验新组合admission及结构饵适配（不要求天气当刻有鱼、不要求库存足够）；任一失败不取消、不退款、不改旧配置。目标完全相同返回NO_CHANGE。合法后若有未完成尝试则按CMD02取消；原地区完整选择存入lastSelectionByRegion，写新selection、preferredBaitId=新bait，清除备用状态；若正在准备则清除旧准备，已结算不回退；pending不可丢弃。如果原enabled且无其他暂停阻断，立即尝试启动新配置；若原未启用则只改配置，不自动开钓。原有满仓、pending等原因仍受新检查约束。切换地区免费。

### CMD06 RESTORE_PREFERRED_BAIT

只在effective bait与preferred不同且为备用状态可用；构造原首选bait选择并用CMD04的完整准入及结构检查。要求已有至少1份，或自动补货按当前储备确实可买≥1；不满足NO_BAIT且旧任务不取消。成功后按换饵取消重启；不再自动从免费饵恢复。若当前未启用，恢复配置不触发补货，库存不足时仍拒绝，待手动购买。

### CMD07 SET_POLICIES

完整Policies替换，不改变已开始尝试的竿线饵或风险；自动处置使用结算时最新策略；补货用下次检查时策略。retain/sell数组各rule id唯一，启用规则OR匹配；P0仅支持FishPredicate单项，复杂AND和TopN拒绝UNSUPPORTED_FEATURE。重量范围至少给一端且min<=max，枚举/ID合法且不得要求未发现隐藏ID（内部合法配置例外）。replenish.batch∈[1,maxBatch]，reserve合法Nat，onInsufficient合法。改变保留规则不追溯立即出售旧鱼；下次智能溢出时重新评估保护，手动锁始终优先。无需取消尝试；如果正在仓库满暂停，可手动RESUME，不自动开始；如果有pending必须先处理。返回变更notice。

## 3. 成长与经济指令（CMD08—13）

| ID / 方法 | 入参及顺序 | 成功状态变更 | 失败与边界 |
|---|---|---|---|
| CMD08 ALLOCATE | points五项Nat→sum>0→sum<=unspent | 逐项加allocated，减unspent；不影响当前cast | 0为NO_CHANGE；超出INSUFFICIENT_POINTS；负数/缺项INVALID_ARGUMENT |
| CMD09 RESET | method FREE/GOLD→sum(allocated)>0→FREE检查等级及次数；GOLD查当前费用和余额 | 所有已分配点返还unspent，allocated全0；FREE增加freeResetsUsed；GOLD扣一次、paidResets+1、写RESET流水 | 无已分配点NO_CHANGE，不扣钱；FREE条件不满足LOCKED；金币不足INSUFFICIENT_GOLD；AD仅走广告事务 |
| CMD10 BUY | offerId存在且enabled/作用域（地区商店须当前地区）→条件→item存在→quantity>0→所有权/库存→余额 | ROD/LINE/REUSABLE数量严格1，扣商品价并新增拥有ID；CONSUMABLE按quantity增加库存，记BAIT_BUY；不自动装备 | NOT_FOUND/LOCKED/ALREADY_OWNED/STOCK_LIMIT/INSUFFICIENT_GOLD；批量购买不自动部分成交，只有自动补货可部分买；FREE拒绝购买 |
| CMD11 UNLOCK_REGION | region存在且未解锁→非隐藏付费/普通解锁路径→条件→余额 | 支付一次unlockCostGold（0不记0值流水），增加unlockedRegions；不切换 | 隐藏地区只能由发现奖励解锁；已拥有ALREADY_OWNED；不足不扣；仅达资格不自动购买 |
| CMD12 EXPAND_WAREHOUSE | tier存在→previousId等于当前tier→余额 | 扣款，更新tier；已有鱼不迁移不复制 | NOT_NEXT_TIER；不能跳档/降级；pending不自动入库，玩家可手动移动 |
| CMD13 EXPAND_TANK_SLOTS | 同仓库链式检查 | 扣款、slotTier升级；旧鱼缸不变 | 同上，不自动购买新鱼缸 |

上述成功操作立即持久化；余额变化写GoldEntry（0变更不写），累加生涯goldIn/goldOut；不发钓鱼XP。金币重置费用报价使用当前配置；新手免费资格按 `level<=freeResetMaxLevel && freeResetsUsed<freeResetCount`；如有新手免费机会仍允许玩家主动选择GOLD（页面应明确提示）。等级/自由点不由命令直接设置。

## 4. 鱼获与水族馆指令（CMD14—19）

### CMD14 SET_FISH_LOCK

入参fishId、locked。必须持有鱼（WAREHOUSE/TANK/PENDING均可）；已是目标NO_CHANGE；更新manualLocked。锁定是防止自动出售，不限制手动转移；解除锁不会自动触发出售。所有鱼的保护由 `manualLocked || anyEnabledRetainPredicate(fish.flags,fish.rarityAtCatch,...)` 计算；不存第二个权威保护状态。体色/重量/捕获首次标签不变。

### CMD15 SELL_FISH

入参非空不重复fishIds、confirmProtected。先验证每个fish存在且持有、所有报价可计算；如果任意manualLocked或自动保护且confirmProtected=false，整批FISH_PROTECTED（提示明确确认后重发）；true代表本次明确确认，不自动解锁其他鱼。按ID稳定顺序出售，统一当前价格；删除持有记录及归属，记每条SALE流水/聚合，增加余额。历史图鉴、纪录及必要档案保持；不发XP，不改变本次自动售鱼广告基数（手动不计）。若包含pending，解除pending归属但保持暂停，玩家手动RESUME。返回所有已售ID和总实际金币。禁止接受客户端报价。

### CMD16 BUY_TANK

入参typeId、slot（1起始整数）。type存在→unlockCondition→slot<=当前slotTier.capacity→该slot空→余额。扣priceGold，分配稳定tankId，建立空鱼缸；不自动移动鱼。失败LOCKED/NO_TANK_SLOT/INSUFFICIENT_GOLD。没有出售或维护接口。

### CMD17 UPGRADE_TANK

入参tankId、typeId。鱼缸存在→目标存在且upgradeFromIds含当前typeId→条件→验证所有现有鱼满足目标生态、单体重量和总空间→余额。以目标type.priceGold作为本次全价（不退旧价；E项设计建议），扣金币并更新typeId，tankId/slot/鱼归属不变；拒绝降级或不兼容，整笔不变。若未来需要差价，必须新增显式配置而非开发者自定。

### CMD18 MOVE_FISH

入参fishId、destination(WAREHOUSE/PENDING/TANK)。玩家不能主动移动到PENDING，拒绝INVALID_ARGUMENT；PENDING只能系统创建。源必须存在；同归属NO_CHANGE。WAREHOUSE目标检查数量+1<=capacity（不自动卖出旧鱼）；TANK目标必须存在，鱼种waterType与tank.waterType匹配，SPECIAL要求compatibilityTags与allowedTags至少交集（若allowedTags为空，普通同水域允许，SPECIAL拒绝）；maxWeightG独立校验。空间 `ceil(lerp(species.aquariumSpace,weightG))` 至少1，当前占用从所有owner派生，目标加入后不超spaceUnits；检查时排除正在移动的同一鱼。更新唯一owner，不生成新鱼、不发XP/金币、不更改档案及锁；PENDING移出后暂停保留直到RESUME。失败TANK_INCOMPATIBLE/TANK_FULL/WAREHOUSE_FULL。鱼缸不自动产出、饲养或繁殖。

### CMD19 BEGIN_AD

入参AdTarget，只创建请求并启动平台播放协调，不直接发奖励。详细校验、锁定、回调及持久化见19。若已有非终止广告请求，AD_IN_PROGRESS；不接受客户端自行上报完整观看或奖励数值。成功回执adRequestId，真实奖励到账以订阅的已提交状态为准。广告失败/取消不扣金币、不消耗日配额。P0不支持内购、强制广告、特殊竿广告。

## 5. 查询接口（Q01—Q16）

查询为同步纯读取已发布的一致视图，不读设备时间，不做存档、不推进随机、不触发成就；时间相关展示由应用tick更新后再取。未完成离线补算时显示上次已提交状态及运行态，不开放写操作。返回深拷贝、必要字段白名单，不直接序列化GameState或GameConfig。隐藏鱼/事件/成就未解锁前不返回ID或描述；普通鱼未发现仅名称/剪影/允许提示，不返回概率、理论最大重量（若产品允许习性提示仍不得精确概率）。对抗中只提供phase/progress/配置允许的encounterKey，不公开实际plannedFish或failure。查询未知、未披露对象都返回NOT_FOUND，不区分隐藏存在性。绝不暴露RNG、保底计数、捕获计划、隐藏条件、未触发奖励。

分页协议：limit为[1,maxPageSize]整数；cursor为不透明的base64url JSON，包含逻辑revision、查询类型、规范化过滤参数hash、最后一项稳定排序键；非法编码/不匹配过滤器INVALID_ARGUMENT；revision变化STALE_REVISION，重新首页。无cursor从第一页；total为本次筛选后总数；末页nextCursor缺省。禁止直接把未筛选数据切页后再过滤；禁止offset因新增鱼重复/漏项。对于查询逻辑版本频繁变化的情况，UI可以保留上一次页快照并明确刷新，不能改用旧cursor跨版本读取。

补充查询 Q17 `equipmentCatalog()`：返回 EquipmentView[]；普通已公开装备及已拥有特殊装备，隐藏未获得特殊竿不展示；竿线物理及有效角色加成字段直接来自配置，不展示鱼种精确权重或隐藏获取条件。消耗饵返回库存，免费饵stock省略表示无限，拟饵返回owned；只展示已公开且能正常取得的饵。按kind（ROD/LINE/BAIT）、id升序。使用资格与余额独立；UI不能从售价推导战力。图鉴未发现时可公开地区仅使用species.publicRegionIds配置，禁止从内部种群反向泄漏。`commandMetadata()` 返回当前revision、nextSeq及runState；player()同时返回下一次临时离线扩展及当前加速有效期。

## 6. 订阅和生命周期

`subscribe(listener)`只在新一致状态公开后调用一次revision；返回可重复执行的取消订阅函数。订阅异常捕获并记录，不影响提交；回调中不得同步重入写状态，若触发dispatch则排队。`tick()`只推进时间，无直接UI动画逻辑；`onHide/onShow/initialize`按19，重复通知幂等。`requestDelete/confirmDelete`走独立恢复入口，双确认见19；删除不需要云端账号。

## 7. P1/P2边界

多预案、TopN/复杂筛选、水族馆命名装饰、分享、研究报告、好友访问、云存档、跨设备、排名和比赛不属于当前应用实现。对于未定义指令直接UNSUPPORTED_FEATURE；不得用空对象伪装成功，也不得在S0/S1提前实现完整页面。
