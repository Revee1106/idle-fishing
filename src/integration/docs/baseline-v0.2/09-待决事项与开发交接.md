本卷跟踪尚未决定的数值和实现边界，已确认修订以00、10—14为准。

## 1. 已确认与未确认的分界

已确认：产品定位、功能及修订优先级、内容预算、八模型、联合模拟、逻辑数据契约、零成本存储、Cocos Code First、运行状态机与事务设计。

## 4. 开发顺序

技术验证（14）→ 正式数据Schema与核心引擎 → 端到端事务 → 数值模拟与基线冻结 → 核心Demo → 完整P0 → 真机及平台发布验收。技术验证可采用少量假数据，不代表正式玩法数值。具体阶段依赖见14。

## 5. 开发交接

开发者先读00、09、11—14，再按任务读取具体功能和模型。明确需求、实现细节、待决参数及测试结果的区别；不得把计划写成实际完成。不得自行增加付费、服务器、编辑器人工依赖或新玩法。数值模拟不证明游戏好玩，仍需真实体验验证。
