## 2. 首任务 SPIKE-001

目标：证明AI能够通过代码和自动化工具维护同一套TypeScript核心，并在真实微信小游戏环境中运行与可靠保存。优先验证成本最高的不确定性：共享包构建、Cocos命令行、微信本地文件、前后台及真机性能。

输入：00—14，尤其09、10、11、12、13。若新仓库，建立最小工程；若已有仓库，先检查实际结构及工具链，避免覆盖既有内容。确认目标AppID、开发者工具权限、Cocos版本和本地构建环境；不可自行购买资源或开通收费服务。缺失工具/账号/真机记阻塞。

范围：一个Boot场景；代码创建两个简单测试页面（按钮、滚动列表、弹窗、切页），简单Tween；共享纯TS测试模块以固定种子生成假事件/金币/进度；虚拟时钟、可序列化状态、测试性离线推进；Node及Web/微信调用共享模块；微信文件多槽最小实现；构建/测试脚本、故障注入和报告。测试假数据不是正式游戏规则；不实现完整八模型、真实鱼种配置、商业化数值、最终美术、云端服务、数据库或新玩法。

建议分三批：A 核心和Node/Web共享；B 微信构建、文件和生命周期；C 真机性能、分包及广告验证。每批记录人工步骤，避免AI声称自动化而实际依赖重复编辑器操作。

## 3. 验收矩阵

| ID | 验证 | 可核验交付 |
|---|---|---|
| T01 | 微信小游戏启动 | 构建产物、开发者工具和真机启动结果，设备及版本 |
| T02 | 共享规则 | 同一源码生成Node/Cocos产物；固定输入结果一致，无手工复制维护 |
| T03 | 确定性随机 | 重启恢复、分批推进与连续推进对照；随机状态一致 |
| T04 | 文件存档 | 三槽读写、校验、损坏槽恢复；不把全损坏当新档 |
| T05 | 故障恢复 | 各关键写入点故障注入、已提交奖励不重复；真机语义单独记录 |
| T06 | 24h离线 | 代表性压力假数据、分片执行、测量耗时/内存/帧阻塞，记录设备；正式阈值及负载在结果后确认 |
| T07 | 迁移 | v1样例迁移v2，失败保留原档；未完成尝试兼容的最小样例 |
| T08 | 生命周期 | 真实前后台及强退、时间回退、原会话截止不重置 |
| T09 | 激励广告 | 有真实广告位时验证完整观看、取消/失败及重复回调；没有则仅适配器桩和去重测试，真实项BLOCKED |
| T10 | 分包与资源 | 最小资源分包构建、加载及包体记录；不依赖远端服务器 |
| T11 | Code First | 代码生成测试页面、列表、弹窗、切换与动画；无需重复人工拖拽 |
| T12 | 可重复构建 | 记录确切Cocos/Node/TS版本与命令，Web及微信构建可重跑；GUI依赖如实记录 |
| T13 | AI修复闭环 | 可复现小缺陷→日志/截图→代码修复→自动回归；实际证据 |

每项结果PASS/FAIL/BLOCKED/NOT_RUN。Spike不以未经验证的硬件性能指标冒充实测；T06用真实结果决定后续预算。T01—T08及T10—T13是技术路线核心验证目标；广告受发布资格制约时可先继续与广告无关的核心研发，但不得视为正式广告通过。核心平台项阻塞需用户评估后方可进入依赖该项的实现。全程无自建后端或收费云服务。
