# 10｜数据配置结构与模型契约 v0.1

**状态：逻辑数据设计已认可；具体字段与可执行Schema仍待实现验证。** 依赖设计基线00—09，尤其02—06及09。本文提出逻辑Schema、字段职责、配置校验及若干待确认的边界处理，不冻结具体鱼种数值，技术路线见11；本卷不引入数据库或HTTP后端。不涉及具体UI。

## 1. 设计目标与边界

新增常规鱼、地区、位置、竿线饵、已支持效果的事件和成就时，仅新增配置与资源即可；八个计算模型使用同一套配置和引擎。新增一种此前不存在的行为、公式或奖励机制仍须扩展引擎并测试，不能把任意脚本写进配置。策划配置是规则输入，不是运行时玩家数据，不是玩家状态；P0随客户端发布且校验，无法保证抵抗恶意修改。数值模拟器可以载入实验配置，但发布配置必须通过完整校验。

设计原则：ID稳定，显式单位，字段职责唯一，零值不等于缺失，引用可验证，计算参数可版本化，玩家档案不被配置修改追溯覆盖。配置中不写针对某条鱼或某件装备的硬编码分支。

## 2. 数据分层

| 层级 | 所含数据 | 生命周期 |
|---|---|---|
| 内容定义 | 鱼种、种群、位置、竿线饵、商店、鱼缸、事件、成就 | 配置发布版本内不可变 |
| 规则参数 | 属性曲线、时间边界、概率上限、成长、价格、离线、广告参数 | 配置发布版本内不可变 |
| 玩家持久状态 | 等级经验、自由点、金币、库存、装备、解锁、仓库、水族馆、统计 | 由合法行为更新 |
| 进行中状态 | 作钓会话、尝试快照、等待阈值和进度、个体及对抗计划 | 跨登录保存，单次行为完成后终止 |
| 历史事实 | 捕获、结算、金币流水、首次、纪录、发现、奖励领取 | 幂等追加或汇总；必要档案永久保留 |
| 模拟专用 | 玩家策略、登录计划、随机种子、批次、断言、结果 | 隔离于生产账号，不作为正式玩法配置 |

运行时通过只读的已解析配置对象取得定义。生产的公开配置只含可公开的描述、已发现内容、物品展示数据和必要的状态；概率权重、隐藏内容条件、保底计数、随机状态不向客户端直接下发。模拟器可访问完整配置。

## 3. 配置目录及基本格式（逻辑建议）

```
config/
  manifest
  rules/{attributes,timing,admission,probability,capture,growth,economy,offline,ads,inventory}
  content/{rods,lines,baits,fish_species,fish_populations,regions,positions}
  content/{day_phases,weather_profiles,event_templates,event_instances}
  content/{shops,achievements,discoveries,tank_types,warehouse_tiers,localization}
  scenarios/{demo_players,simulation_cases}
```

文件名表示逻辑集合，不预设存储介质。策划可以用表格维护批量配置，导出规范JSON供校验、模拟和正式引擎使用。机器读取格式、最终Schema实现工具在架构阶段决定。

`ConfigManifest`：schemaVersion（结构版本）、configVersion（发布配置版本）、rulesetVersion（公式语义版本）、contentPackId、contentHash、enabledFeatures、各集合清单及校验摘要。相同版本不得对应不同内容；实验版本有独立标识。新增内容不复用已停用ID，显示名称独立于ID。主键示例 `fish.common_carp`、`region.pond`、`position.pond.near_shallow`；示例不锁定具体命名或正式数值。

字段约定：下文类型 `id` 为非空稳定标识；`uint` 为非负整数；`positive` 为有限正数；`ratio` 为[0,1]；`mult` 为有限非负倍率，1为中性；`map<K,V>` 为按枚举或ID索引的映射；`ref` 必须指向存在且合法的定义。可选字段应明确默认值，必填字段缺失拒绝加载。禁止NaN、无穷、非法负值。表中字段名为建议契约，待评审后进入机器Schema。

## 4. 单位与精度

| 数据 | 逻辑单位/精度 |
|---|---|
| 鱼重量与纪录 | 整数克，至少1克；区间互斥 |
| 距离、深度、线长 | 米，配置可有小数；准入采用同一精度，不按展示四舍五入 |
| 拉力 | 牛顿，允许有限小数；持续与峰值分别记录 |
| 动作时间、事件时间 | 配置现实秒；运行时逻辑时间戳与时长建议整数毫秒；计算中保留进度余数 |
| 游戏世界时间 | 独立现实到世界时间的12倍映射；环境时段按游戏时钟 |
| 属性、金币、XP、鱼数 | 非负整数；金币与XP统一在结算边界取整，建议成功奖励四舍五入，失败XP向下取整，升级需求向上取整 |
| 权重、概率、倍率 | 有限数值，权重非负，概率[0,1]，倍率1为中性 |

无限等级不等于允许整数溢出；技术设计须选择可安全序列化的大整数/定点或等效方案，禁止静默溢出。具体时间量化、随机算法和跨语言一致性留至核心架构；同一实现、同一输入应可复现。价钱最低1金币、XP成功最低1等尚未确认，本文建议成功鱼售价至少1、成功常规经验至少1，失败经验可0；数值模拟时检查其合理性。

## 5. 共用配置结构

### 5.1 条件表达式

`Condition` 为受限声明式结构：`all`、`any`、`not` 组合及白名单叶节点；叶节点包含 `type`、受类型约束的参数、比较符及阈值。可用条件包括 levelAtLeast、regionUnlocked、positionDiscovered、discoveryOwned、equipmentOwned、speciesDiscoveredCount、recordWeightAtLeast、achievementCompleted、statAtLeast、currentRegion/Position/Bait、dayPhase、weather、eligibleAttemptsAtLeast、outcome。只允许适合当前调用节点的数据域。隐藏发现、成就、商品、地区使用同一条件求值器但各自受限。

金币费用不是普通条件表达式的副作用，`unlockCostGold` 或商品价格单独声明，并在事务中扣除。条件求值必须纯读取，不抽随机、不发奖励、不修改状态。引用图校验不可达、循环前置及广告依赖；常规路径不得要求极罕见鱼或隐藏发现。

### 5.2 奖励与效果

`Reward`：`type` + 对应payload，例如 gold(amount)、xp(amount)、bait(baitId,count)、equipment(equipmentId,duplicateRewardId)、discovery(discoveryId)、cosmetic(cosmeticId)。一组奖励拥有稳定 rewardId；一次性资格拥有稳定 claimKey（玩家×奖励目标），不能随配置版本改变而重置。重复特殊装备按已配置普通奖励转换。禁止永久属性奖励、概率保底奖励及直接广告特殊竿。

`Modifier`：目标作用域（region/position/species或组合）、效果通道、倍率/明确禁止、有效时段。通道限定 `activityRate`、`speciesWeight`、`weightGradeWeight`、`colorWeight`、`temporaryPopulation`。各通道独立，不能用一个含糊的“收益加成”同时影响多个模型。禁用优先于倍率下限。事件时钟和作用域可验证。

## 6. 角色、装备与鱼饵

| Schema | 必需字段/结构 | 关键约束 |
|---|---|---|
| AttributeRules | initial{strength,skill,agility,perception,luck}；pointsPerLevel；curves[effectId]{K,maxEffect} | 五属性非负整数；K>0；效果ID固定且与计算模型一致；初始各10、每级5为示例 |
| RodDef | id,nameKey,type,quality,isSpecial,statBonus, maxCastM,maxDepthM, capacityN,control,sensitivity,reelEfficiency,castBaseProfileId, acquisitionRefs,useCondition | 物理性能与角色属性分开；普通竿luck=0；特殊竿禁止商店或广告直接取得 |
| LineDef | id,nameKey,material,quality,lengthM,capacityN,stealth,burstBuffer,signal,acquisitionRefs,useCondition | stealth/burstBuffer在[0,1]；有效长度由AdmissionRules计算，禁止重复保存为权威配置 |
| BaitDef | id,nameKey,kind(FREE/CONSUMABLE/REUSABLE),attraction, speciesPreference,weightPreference,acquisitionRefs,useCondition,adSupplyTier | 唯一基础免费饵；消耗型抛竿扣1；拟饵永久拥有；不以售价或稀有度自动推导效果 |
| ShopOffer | id,shopScope, itemRef, priceGold,purchaseCondition,enabled | 竿线及拟饵唯一购买；消耗饵可重复；同一种消耗饵的参考价唯一，不受取得途径影响 |

属性曲线采用固定效果ID，例如 castAgility、reelAgility、prepareAgility、bitePerception、fightStrength、strengthRisk、hookRisk、operationErrorRisk、speciesLuckByRarity、weightLuckByGrade、colorLuckByColor、eventLuckByProfile。不要给每项属性只设一个全局K。控鱼、灵敏度、信号及效率的量表由相应规则参数统一定义（可采用正数倍率或归一值，不得混用）；建议明确哪项是直接倍率、哪项是曲线输入。

鱼饵偏好拆开：`speciesPreference` 含 default、byDiet、bySpecies、byRegionSpecies；按默认→食性→鱼种→地区鱼种覆盖，最终只取一项；`weightPreference` 含defaultByGrade及可选bySpeciesGrade（建议沿用同样覆盖语义）。未指定继承，显式0不继承。鱼种定义食性，鱼饵配置维护偏好唯一来源。鱼饵参考价从规范经济价格配置获取，不在每个种群重复维护。

## 7. 地区、作钓位置与种群

| Schema | 字段 | 约束 |
|---|---|---|
| RegionDef | id,nameKey,waterType,hidden,unlockCondition,unlockCostGold,weatherProfileId,eventPoolIds | 初始地区默认解锁且免费；隐藏仅合法发现解锁；切换不收费 |
| PositionDef | id,regionId,distanceBand,depthBand,distanceM,depthM,hidden,discoveryId,enabled,biteBaseSeconds | 地区内分类组合唯一；仅配置实际存在位置；未配置组合不存在；enabled用于停用而非制造动态天气禁区 |
| PopulationDef | id,positionId,speciesId,baseWeight,activityMultiplier,weightGradeMultipliers,colorMultipliers,environmentProfileId,eligibilityCondition | 同位置同鱼种常规种群唯一；每位置可配置不同分布；权重0为禁止；种群无有限数量库存 |
| AdmissionRules | lineReserveRatio | 有效线长=总长×(1-预留比例)，比例小于1；只使用物理位置及装备准入字段 |

同一个鱼种可被多个位置种群引用，不重复定义基础属性。种群位置级是唯一来源；策划工具可批量生成地区默认分布，但最终发布配置解析为明确位置数据，避免隐式继承造成歧义。地区独立鱼种数根据不同位置speciesId去重计算。

## 8. 鱼种、重量与体色

`FishSpeciesDef`：id、nameKey、rarity（common/uncommon/rare/epic/legendary对应五档）、diet、waterType、visibility（normal/hidden）、minWeightG、maxWeightG、weightReferenceG、wariness、baseActivity、weightBands、colors、combat、xp、price、habitHintKeys、aquariumProfile。不得把重量档次写进鱼种稀有度。`weightReferenceG` 必须>0；若捕获、XP、价格需要不同参考重量，可在各子对象显式覆盖，而不是默默使用不同单位。普通体色使用固定ID `normal`。

| 子对象 | 字段 | 约束 |
|---|---|---|
| WeightBand | grade,minG,maxG,baseWeight,shapeAlpha | 六档闭区间整数克、按顺序连续且互斥；α>0；基础权重可0但总权重>0 |
| ColorDef | colorId,baseWeight,priceMultiplier,xpBonusRate,assetKey | 普通体色必须存在且正权重，普通价倍率1、额外XP0；特殊体色集合由鱼种声明 |
| CombatProfile | referenceG?,sustainN,burstExtraN,sustainExponent,burstExponent,hookDifficultyCurve,baseHookRisk,operationErrorProfileId,fightTimeProfileId | 持续拉力正、爆发可0；同种同重量确定；脱钩曲线可非单调但始终合法 |
| XpProfile | baseXp,referenceG?,weightExponent,weightMinMultiplier,weightMaxMultiplier,firstSpeciesReward,firstRegionReward,firstColorRewards,recordMilestoneRewards | 基础XP包含稀有度难度价值；发现与里程碑独立，不以颜色概率重复计奖 |
| PriceProfile | baseGold,referenceG?,weightExponent | 默认次线性，独立曲线；不含等级、地区、纪录倍率 |
| AquariumProfile | spaceCurveId,compatibilityTags | 空间依据个体重量及物种配置，不能等同鱼数量；无产出或成长 |

建议重量离散算法（D04）：对档位整数闭区间[a,b]，抽U∈[0,1)，返回 `a+floor((b-a+1)*U^alpha)`；因数值误差可能越界时仅修正到合法边界。每个整数均有非零可达概率；最大值不要求随机数恰为1。连续难度公式只使用最终整数重量。区间内随机不受幸运/鱼饵再修正。例子：50–199g、200–999g、1000–4999g……各档无交叉。

## 9. 环境及随机事件

| Schema | 字段 |
|---|---|
| WorldTimeRules | worldTimeAnchor, speedMultiplier=12, dayPhaseScheduleId |
| DayPhase | id,startGameMinute,endGameMinute；全天无重叠、无缺口 |
| WeatherProfile | id,weatherStates,initialWeights,transitionWeights,durationRangeGameSeconds；地区独立 |
| EnvironmentProfile | activityByPhase/Weather,speciesWeightByPhase/Weather,gradeModifiers,colorModifiers,explicitRestrictions |
| EventTemplate | id,category,triggerNode,allowedConditionTypes,allowedEffectTypes |
| EventDef | id,templateId,scope,eligibilityCondition,baseChanceOrSchedule,durationGameSeconds,modifiers,rewards,repeatPolicy,stackGroup,luckProfileId?,pityProfileId?,replacementActionSeconds? |
| PityProfile | id,eligibleAttemptCondition,progressCurve,maxModifier,resetRule,claimKey |
| DiscoveryDef | id,hidden,prerequisites,sourceRefs,unlockTargets,logKey |

触发节点建议固定枚举：ENVIRONMENT_BOUNDARY、BEFORE_FISH_DRAW、AFTER_ATTEMPT_SETTLEMENT、ENCOUNTER_PRESENTATION。替代型每次最多一个、总概率有限；额外型明确是否要求成功。环境事件不引用个人幸运/保底；软保底仅用于允许的关键地图、线索、特殊竿。遭遇模板引用当前已生成的鱼而非抽取新个体。环境临时种群必须有完整合法定义、有效期限和适用位置。不能用事件改变额定负载硬限制、理论重量上限或作钓物理位置。

概率规则包含：stealthMaxLoss、speciesLuckCurves、gradeLuckCurves、colorLuckCurves、eventLuckCurves、environmentMultiplierBounds（按通道）、specialColorTotalCap、replacementEventTotalCap。倍率上限与概率上限不是同一字段。建议特殊体色合计上限通过将特殊类概率同比缩减至上限、剩余概率给普通体色实现；不改变各特殊色内部相对比例。0权重保持0。权重抽样候选按稳定ID排序，不使用数据库返回顺序。

## 10. 计算规则参数集合

| 规则集 | 必要参数（均为逻辑字段） |
|---|---|
| TimingRules | castProfiles（基础时间和实际距离曲线）、prepareBaseByOutcome、reelOperationSeconds、reelBaseMps、signalCombineWeights/curve、biteDemandTriangle(a,mode,b)、activityBounds、stageMin/MaxSeconds、emptyPoolTimeout、fightTimeProfiles |
| CaptureRules | forceReferenceN、strengthK/maxRisk/gamma、hookSkillCurve、controlCurve、errorSkillCurve、operationErrorBaseRisk/extraForceProfile、strengthFailureProgressRange、hookFailureProgressRange、sustainCheckProgress、burstProgress、tiePriority |
| GrowthRules | nextLevelBaseA/exponentB、pointsPerLevel引用、failRatio/failXpCap、capabilityExponent、recordRewardPolicy、firstRewardPolicy、milestoneGrades |
| EconomyRules | rounding、minSaleGold、resetInitialGold/resetMultiplier/resetCapGold、beginnerFreeResetPolicy、baitReferencePricePolicy |
| InventoryRules | defaultWarehouseTier、overflowPolicies、autoRetain/saleConditions、baitStockLimit、replenishPolicy |
| OfflineRules | baseHours=8、maxHours=24、permanentTierByLevel、freezePolicy、sessionBoundaryPolicy |
| AdsRules | speedBonus/durationRealSeconds/dailyLimit、offlineExtension/dailyLimit、offlineGoldRate/cap/claimWindow、baitSupplyTable/quotaGroup、resetDailyLimit、quotaTimezone |

pointsPerLevel只定义一次，成长规则引用属性规则；时间曲线及风险曲线各自拥有唯一参数定义。装备性能、鱼种属性和成长价格不能由同一个quality分数代替。广告只进入执行速度、离线额度或合法奖励结算，不是幸运修正。重置计数只在成功金币重置后增加，免费/广告不计。广告金币基数按新捕获自动售鱼收入减实际消耗参考价，独立于购买流水。

三角需求建议校验a>0、a≤mode≤b且(a+mode+b)/3=1；若策划希望均值不为1，必须明确基础等待定义变更，不能无意改变期望。参考时长、速度、倍率和概率的有效域都由加载器校验。D01/D05/D06仍需确认具体函数与边界组合，不能仅凭字段表认为已经可执行。

| TankInstance | tankId,typeId,ownedSlotId,fishIds或由鱼归属索引派生；P1名称/装饰 |
| AdEntitlement | entitlementId,type,localAdRequestRef,validityWindow,quotaDate,consumedAt,sessionRef? |
| OfflineReport | reportId,sessionId,start/end,actualFishingTime,pausedTime,lostTime,attemptCounts,fish/XP/gold/bait aggregates,highlightRefs,adClaimStatus |

`level` 与 `xpInLevel` 不能与 `totalXpEarned` 同时独立手工修改；累计经验用于统计，升级状态由统一成长操作更新。自由点守恒：累计发放=已分配+未分配（无其他获点渠道）。鱼的权威归属唯一，仓库和鱼缸索引由其派生或在同一事务维护。尝试的ID在抛竿生成；个体候选ID可在咬钩生成，成功后成为持有鱼ID；失败不进入持有集合。

随机源需要可复现且可持久化；建议环境、鱼种、重量、体色、对抗、个人事件分离随机流，稳定种子推导方法留架构，已经抽样的阈值/个体/节点持久化，不通过重放客户端请求重抽。正常UI不展示随机状态；本地文件并非可信安全边界。

## 13. 历史、结算和统计数据

`AttemptSettlement` 以attemptId唯一：结果类型、失败分类及节点、有效进度、实际耗时、鱼饵消耗、鱼获处理、XP、事件奖励、关联流水、结算版本。`GoldLedgerEntry` 以稳定操作ID唯一：原因、金额、余额前后或等效可审计字段、配置版本、时间、attempt/session关联。`RewardClaim` 以claimKey唯一；`DiscoveryLog` 保存重要发现；`RecordHistory` 按recordScope与scopeKey存储新旧重量、fishId、时间和档案引用；`StatAggregate` 按玩家、鱼种、地区等已批准维度汇总。普通已售鱼明细只在汇总、交易幂等和审计需求满足后清理；首次、纪录、关键事件保留所需快照。历史鱼的重量体色不被配置覆盖；出售按交易时现行价。

建议离线广告基数单独持久化 `newFishAutoSaleGold`、`consumedBaitReferenceGold`、`eligibleGold`、结算时政策版本、claimKey，避免领取时重新读取变化的库存或价格。未完成尝试跨在线/离线边界时，饵成本按实际抛竿消耗时间归属、售鱼收入按出售发生时间归属；是否增加更严格的跨会话匹配需评审D13。

## 14. 八个模型接口契约（语言中立）

| 模型 | 输入 | 输出 | 纯计算/状态 |
|---|---|---|---|
| 01 effectiveStats | 基础属性、分配属性、当前竿加成 | 五项有效属性 | 纯计算 |
| 02 checkAdmission | 地区/位置、资格、竿线、准入参数 | 通过、失败原因集合、所需/有效线长 | 纯计算；不消费物品 |
| 03 timeModel | 快照、时间参数、环境速率、广告速率、计划节点 | 各阶段工作量、动态速率、下一边界 | 纯计算；进度由状态机推进 |
| 04 speciesDistribution | 位置种群、饵、隐蔽、幸运、咬钩环境、规则 | 有效候选及权重；总权重0原因 | 纯计算；抽样由随机服务执行 |
| 05 generateIndividual | 鱼种/种群、饵、幸运、环境、随机输入 | 重量档、整数重量、体色、基础对抗属性 | 确定随机输入下可复现 |
| 06 planCapture | 个体、属性/装备快照、准入线长、规则、随机输入 | 客观物理结果、理论成功率、对抗时长及节点计划 | 只生成一次；执行不再次抽总概率 |
| 07 calculateXp | 结果、个体、实际进度、能力、历史首次/纪录、规则 | 各项经验及一次性奖励建议 | 纯计算；成长应用由结算器负责 |
| 08 economy | 鱼个体、当前价格版本、库存/余额、规则 | 售价、购买/重置报价、补货计划、广告奖励基数 | 纯计算；入账扣款由事务负责 |

候选计算复用同一函数服务等待时的有效性与咬钩时抽样；等待速率不能使用幸运修正后的总权重。引擎内部不调用真实系统时钟、客户端UI或平台广告API；时钟、随机、配置版本通过明确输入注入。模拟器的策略层可发合法操作，不允许直接改成长状态绕过规则（固定/压力测试的初始化例外须标记）。

## 15. 配置加载与静态校验

加载顺序：清单与版本→Schema和数值类型→ID与外键→继承解析→内容及概率校验→解锁可达性→核心保底场景检查→生成不可变运行时快照。发布前以下错误必须阻断：

- 重复ID、无效引用、缺少必填字段、非法值、概率越界、明确禁用被下限复活；区间不连续/交叉/越过鱼种范围，正常体色缺失。
- 普通竿加幸运、特殊竿通过商店/广告获得、广告独占必要内容、地区存在循环前置或初始装备不可获得。
- 地区无可用作钓位置、初始竿线不能到达初始配置、基础饵在常规位置的合法环境无有效种群（除明确允许的短时环境沉寂，且须定义恢复）。鱼种有正分布但其重量池全0必须在合法组合中排查；稀有体色为0不影响普通体色。
- 临时种群引用非法、事件时间重叠规则缺失、环境事件带个人幸运、软保底作用于稀有鱼/重量/体色、无合法重复奖励策略。
- 价格负数、免费饵非零价、装备重复购买设置、仓库扩容不递增、升级需求非正、重置无封顶、广告超24小时或非法效果。
- 解锁资格或奖励引用不存在的统计指标、事件阶段条件读取尚未生成的个体、普通成长依赖隐藏内容。

需要模拟而非仅靠Schema证明：初始捕获率/稳定正收益、五属性策略优势、回本周期、长期经济、稀有发现周期、广告差距、失败经验防刷。发布配置不得带缺失待定参数；实验配置明确标记，未完成的规则不以任意默认值绕过。

## 16. 原始边界提案与最新决策

下表保留原始提案作为实现参考；用户确认的玩法子项及仍待决内容以09与12为准。未获明确确认的细粒度建议（含同额定上限鱼线优先、跨日时区等）不自动冻结。P0无服务端鉴权。

| ID | 建议契约 |
|---|---|
| D01 | 工作量和现实时间分开。对动作/等待设执行速度上限及现实最小时间，广告加速不突破最终最小值。空池时暂停咬钩进度，累计无有效池的实际作钓时间达到独立超时则空竿；离线冻结期间不累计。还须设置整次等待硬超时（避免反复空池无限等待）。有鱼但到硬超时未达需求时不强制抽鱼，允许空竿。参数须模拟，不能让正常有效鱼群频繁超时。 |
| D02 | 建议半开环境/广告区间[start,end)，同时间先推进至边界，再更新环境与广告状态，再处理当刻咬钩/节点；到离线截止时允许已达完成条件的结算，但不得再启动新尝试。对抗同刻失败优先客观负载→操作负载→力量不足→脱钩，同额定上限暂建议鱼线优先。具体优先级需确认。 |
| D03 | 有正鱼种权重但有效重量池全0时排除该鱼种；等待有效性同样排除。常规配置组合应校验此类冲突，显式针对性巨物饵允许排除某些鱼种但不得在所有可达位置都不可用。禁止体色永远保持0。 |
| D04 | 使用第8节整数闭区间离散抽样；所有档位边界一致，最小最大理论值可达到。 |
| D05 | 建议活动度按适配候选的基础种群权重（不含幸运、隐蔽性和鱼饵相对偏好倍率）加权平均鱼类活动×种群活动×环境活动；明确禁止/零偏好/零重量池排除。鱼饵基础吸引力另乘一次。环境通道独立限幅。具体活动聚合参数仍待验证。 |
| D06 | 控鱼进入力量相对难度一次，额外对抗时长复用该结果；即使额外对抗为0，基础收线仍有正时长，必经持续与爆发节点依附整个收线进度，不跳过。 |
| D07 | 建议手动锁>自动保留>自动出售/智能清理；捕获前若满且无允许处理空间则暂停；若仍发生保护新鱼无法入库，保留一条待处理鱼并立即暂停（不增加可重复捕获容量），玩家处理后恢复；不丢鱼、不自动卖保护鱼。待处理鱼成功奖励已结算，可直接转入适配鱼缸；广告只计符合条件的自动出售及饵消耗，跨会话细节仍待定。 |
| D08 | 建议实际纪录每克刷新均记录，但额外XP仅达到相对或绝对最小提升门槛时发放，比较基准为上次获得纪录XP的重量而非上次实际纪录。首捕建立基准，一次性等级里程碑独立结算。阈值/奖励上限待模拟。 |
| D09 | 建议当前尝试持有启动时规则版本及配置引用至结算，等待阶段使用该规则解释真实时间的环境变化；新尝试使用最新版本。暂停只冻结作钓，世界时钟继续；恢复时使用当前世界环境，不补发暂停期间的个人捕获事件。旧版本配置留存期限与强制迁移策略待架构。 |
| D10 | 建议库存不足下一次抛竿时批量补货；允许部分批次，库存上限亦限制购买量。备用基础饵只改变effectiveBait，不抹掉preferredBait；仅玩家手动恢复首选饵（已确认）。 |
| D11 | 替代事件预设合法回收耗时且有唯一结算，空池不强制触发，只有独立明确条件的事件可使用独立触发节点。保底只计符合条件且非取消的有效尝试，领取后按一次性规则关闭。 |
| D12 | 整数金币/XP/重量/属性，概率、时间进度保留计算精度；统一舍入边界；生产随机实现和大数方案留架构。 |
| D13 | 会话权益、广告凭证、跨日配额、领取窗口、并发幂等单独存储；P0本地配额及回调去重；固定业务日时区、跨会话耗饵基数待确认。 |
| D14 | 保留不可变捕获档案与必要历史快照；普通已售鱼汇总后清理，幂等键不随明细删除提前失效。版本、恢复、账号删除策略留架构。 |
| D15 | 模拟玩家画像、百分位阈值、广告差距上限、随机种子批次由模拟专用配置管理；不混入正式规则，具体数字待模拟规格。 |
| D16 | 当前Demo内容预算及候选清单沿用07/08；真实鱼类生态核对及全部实际配置另行完成，本文未给出正式数值。 |
