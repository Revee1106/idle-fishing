# 19｜平台适配、持久化、广告与版本接口详细设计

适用P0，纯客户端。依赖15—18。微信真实文件写入、广告回调、生命周期、BigInt及构建能力必须在SPIKE-001验证；以下接口设计不等于真实平台已经通过。禁止引入自建后端、HTTP API、数据库或付费服务。平台适配可异步，所有业务状态修改仍通过单一应用队列。

## 1. 平台端口

## 2. ClockProvider 与应用时间线

保存 `cursorMs` 为逻辑业务时间，`clock.highWaterMs` 为已经接受的最高有效现实时间，`lastWallMs` 为最近接受的设备样本。应用启动先读取wall；若wall小于highWater，进入CLOCK_ERROR时间冻结（不回拨cursor，不发离线收益、不刷新日配额）；保留未完成尝试。可只读浏览，不能通过手工修改配置绕过时间异常；当wall>=highWater后恢复。时间前跳不能完全验证真实性：前台使用单调差值推进，不采纳设备时钟大幅跳变作为挂机收益；重新进入前台时允许受离线cap限制的正时间差。初期不宣称强反作弊。

正常前台建立锚点 `anchorLogical=cursor, anchorMono=monotonicNow`；每次tick/指令用 `target=max(cursor,anchorLogical+(monoNow-anchorMono))`；若mono回退则重新建立锚点，当前差值为0并记录；读取wall检查回退及明显跳变。不得在每帧按墙钟补发时间；正常允许设备时钟采样微小误差，具体容差为cfg.persistence.clockToleranceMs（Spike建议2000ms）；前台wall落后highWater不超过容差时忽略wall并正常按单调时钟推进，超过则冻结；启动/恢复时严格禁止回拨；每次接受推进目标后highWaterMs=max(旧highWaterMs,已接受目标)，lastWallMs仅在接受有效墙钟样本时更新，两者同业务状态持久化；业务时间、广告有效期和世界时间统一使用已接受逻辑时间，不得一条规则使用原始Date.now。onHide先推进至当前有效前台时间；onShow使用墙钟与已存highWater比较，锁离线target；前台恢复重新建立单调锚点。任何正跳跃仅可发至已锁deadline；超过部分世界推进，无个人收益。

业务日计算 `day=floor((acceptedUtcMs + quotaTimezoneOffsetMinutes*60000)/86400000)` 转十进制ID；UTC+8为E10建议，时区不跟随手机地区设置。day只前进不回退。广告到期和领取窗口使用同一逻辑现实时间，不受12倍世界加速。当前尝试即使时钟冻结也保留已抽样内容，恢复不重抽。应用事件必须有显式有效at，不允许核心读取系统时间。

## 3. PRNG 与随机输入契约（E09）

使用 xoshiro128** v1；每流状态4个无符号32位整数且不可全0。种子32位；UTF-8流名通过FNV-1a 32位（初值2166136261，每字节xor再Math.imul(16777619)，>>>0），与rootSeed异或作为z；连续4次 `z=(z+0x9e3779b9)>>>0`，混合 `v=z; v=Math.imul(v^(v>>>16),0x85ebca6b)>>>0; v=Math.imul(v^(v>>>13),0xc2b2ae35)>>>0; v=(v^(v>>>16))>>>0` 得到四词；若全0则s0=1。此规则是本项目种子派生协议，不宣称密码学随机。

```ts
function rotl(x: number, k: number): number {
  return ((x << k) | (x >>> (32-k))) >>> 0;
}
function next32(s: [number,number,number,number]): number {
  const r = Math.imul(rotl(Math.imul(s[1],5) >>> 0,7),9) >>> 0;
  const t = (s[1] << 9) >>> 0;
  s[2]=(s[2]^s[0])>>>0; s[3]=(s[3]^s[1])>>>0;
  s[1]=(s[1]^s[2])>>>0; s[0]=(s[0]^s[3])>>>0;
  s[2]=(s[2]^t)>>>0; s[3]=rotl(s[3],11);
  return r;
}
function nextU53(s: [number,number,number,number]): number {
  const a=next32(s)>>>5, b=next32(s)>>>6;
  return (a*67108864+b)/9007199254740992;
}
```

流名固定 `wait`, `species`, `individual`, `capture`, `personal-event`，环境流按 `JSON.stringify(['environment',configVersion,regionId])`；不同流懒初始化使用固定派生算法并立即纳入state.rng，初始化不消耗其他流。每个逻辑抽样固定两次next32；抽样顺序：进入WAITING一个wait U；有效咬钩个人替代候选非空抽1；正常鱼抽species 1、individual 3、capture 5；额外事件按18顺序抽；天气初始化/切换各2，环境事件满足检查且未被stack阻断时每个1。查询、非法命令、空池无鱼、已结算节点、广告发奖不额外抽鱼随机。已取消尝试的已用随机数不回滚。所有state变换在候选RNG副本上执行，事务失败不污染原状态。保存每个流完整状态及已抽出的计划。跨版本保留流名和算法；改变算法须新engineVersion及兼容迁移。U53分辨率和 Math.pow/sqrt/浮点边界需Node、Cocos Web、微信真实运行一致性测试；若不一致，先由设计负责人决定统一数学实现，禁止开发AI私自引入不同算法。

## 4. SaveRepository 物理协议

目录（仅USER_DATA_PATH内部）：`idle_fishing/save_slot_0.json`、`save_slot_1.json`、`save_slot_2.json`，`deletion_marker.json`。可有临时诊断文件，不依赖manifest。每槽独立SaveEnvelope：magic、format=1、revision(Nat物理递增)、epoch、payload（规范JSON字符串，GameState的完整内容）、sha256。校验计算：按固定字段顺序序列化 `[magic,format,revision,epoch,payload]` 的UTF-8 SHA-256小写十六进制；payload递归对象键按UTF-16排序，数组顺序不变，所有Nat为字符串，禁止NaN/Infinity/undefined。使用同一纯TS SHA实现或经跨运行时验证的适配，不能用非密码学校验冒称SHA256。哈希仅防意外损坏，不是防篡改签名。存档不保存可重新生成的公开查询视图；但完整保存随机、时间游标、配置/引擎版本、已抽样计划、统计、报告及幂等键。

### load() → LoadResult

1. 检查删除标记（第7节）；有效标记限制可用epoch，标记损坏拒绝恢复旧槽。
2. 读取3槽；明确不存在忽略；IO失败标记不可判断，不把它当EMPTY。逐个验证magic/format/hash、payload JSON结构、revision/epoch与内部saveEpoch一致、版本基本可识别、状态不变量。旧Schema先用旧版结构验证，不用新版字段要求误判损坏。LoadResult.VALID.state以unknown返回，schemaVersion/epoch来自已验证旧档；应用完成迁移及新版校验后才转为GameState。
3. 选择最高revision有效槽，BigInt比较；若同revision不同payload或无删除标记但多个有效epoch，返回CORRUPT，不任意选。较新槽完整但版本不支持时返回UNSUPPORTED，不能自动选较旧支持槽造成回退。完整合法最高槽损坏但低槽有效时返回VALID recovered=true并记录警告。所有槽不存在且无异常标记→EMPTY；存在但均坏→CORRUPT；只有有效删除标记禁止旧档→DELETED。权限错误等无法确定是否存在返回CORRUPT并附诊断，不自动新建。
4. 启动先扫描，再迁移；当前已提交状态不可修改，调用方取得副本；若已恢复备份，之后新的提交物理revision仍基于最高可信可用revision。损坏槽不计revision（不接受任意损坏字符串推高），旧的相同revision槽会被轮换清理。

### beginEpoch(epoch)

仅在EMPTY或DELETED且明确新建存档流程时调用；检查无合法其他epoch或标记允许新epoch。将带校验的marker写为允许该新epoch，重新读取验证，之后才创建第一份存档。若marker已经允许同epoch幂等；存在旧有效状态返回COMMAND_CONFLICT。正常首次新建也建立marker，避免今后多epoch歧义。初始化失败不能悄悄回退到删除前世代。

### commit(state,expectedRevision) → CommitResult

expectedRevision为最近成功load/commit的**物理**revision；null仅首次。重新核实当前有效槽或应用独占写入锁下的已知revision，若不一致返回CONFLICT。候选状态通过Schema与I01—12，序列化、计算hash，新revision=(expected??0)+1。选槽规则：优先空/无效槽（id升序）；否则在非最高有效槽中选revision最小（id升序）。永不覆盖最后最高有效槽。写入完整字符串，重新读取并验证字节内容/hash/revision/epoch/state；成功则COMMITTED，并更新当前物理revision。无需额外“提交指针”，最高完整有效槽即提交点，崩溃后可认领成功写入的候选。写失败或readback异常不能假定未写：返回UNCERTAIN，停止业务写入，立即重新扫描。若发现完全匹配的新候选revision/hash，则认定已提交并恢复该状态及回执；若明确仍为旧版本且没有新候选，则未提交，保留旧状态并返回SAVE_IO；不能确认则保持RECOVERING/ERROR，不继续重试资产操作。直接重复commit旧expectedRevision必须CONFLICT，不能重放。写前Schema错误为FAILED（确定未写）。禁止在同一个存档目录并行写槽；只允许一应用实例，P0不宣称跨进程/跨设备CAS可靠性。

## 5. 持久化节奏与故障恢复

逻辑事务先构造candidate，普通tick可发布一致内存状态并标dirty；定期保存整个candidate（cfg.persistence.autoSaveIntervalMs，Spike暂定30秒现实有效运行时间）。玩家写命令、关键奖励、广告请求/回调、离线开始/目标锁定/检查点/结束、版本切换必须提交后才确认结果。检查点按cfg.persistence.checkpointMaxNodes或真实耗时预算，不以每帧写盘；每次`advanceUntil`返回mustCommit后在继续推进前立即提交。触发重要奖励的同刻事件组不可先向UI宣布到账再写盘。若普通状态尚未持久化且写入失败，保留上次已提交状态作为恢复点，禁止继续接受付费/资产指令；恢复后确定性重算，可能丢失未保存的普通进度。不可承诺100%防数据丢失。

崩溃点：写入前、部分写、完整写未返回、校验前、校验后未刷新UI、已返回回执后。恢复只看完整有效版本，不按UI是否看到动画决定是否发奖。任何checkpoint必须同时包含余额、库存、历史、随机、当前phase/work、离线session/settledUntil、奖励键及命令回执；禁止拆成若干不同时间的文件独立提交。

## 6. 初始化、生命周期与应用队列

ApplicationApi.initialize仅单次并发（共享正在进行的Promise）：校验当前发布包→load→EMPTY时初始化新档（或DELETED后明确新建）→旧Schema迁移→加载旧版本依赖→恢复原offline（若无offline且有前台崩溃痕迹，以最后有效cursor作为合成离线开始，锁一次额度，不假设onHide必执行）→锁补算目标→分片补算→必要版本切换→最终提交→RUNNING。CORRUPT/UNSUPPORTED/MIGRATION_FAILED不自动新档；保留源文件及诊断，开放只读错误界面和明确删除/恢复入口。初始化期间不调用普通dispatch。

单一FIFO应用队列：玩家指令、tick、onHide、onShow、广告平台结果等统一入队。内部任务不等待依赖后续队列事件的Promise，尤其BEGIN_AD持久化请求后释放队列，再启动SDK播放，结果通过内部回调消息入队。tick可以合并连续未执行的tick（保留最新目标，不跨越已排队命令/生命周期），不能合并资产命令。任何状态变更前先处理已到时间节点（18）。UI订阅只接受已公开一致状态。`onHide`重复时若已有offline且未恢复RUNNING，返回无变化；第一次进入后台先尝试提交离线会话，失败保留最近有效槽，不依赖系统回调必完成。`onShow`重复时共享同一补算任务；若已RUNNING且无offline仅重建时间锚点，不额外创建离线收益。补算中再次HIDE/SHOW记录最新生命周期，原会话不重开；恢复完成后如果仍在后台，新会话只在确实恢复在线的有效边界后才开始，若从未恢复前台则保持同一旧会话且不发额外额度。补算目标锁定到完成间的真实耗时只推进世界，不发钓鱼收益。所有平台异常记录错误码，不静默丢弃关键状态。

## 7. 删除、备份和裁剪

`requestDelete()`仅应用层发起，不清文件；返回一次性token及expiresAt（cfg.persistence.deleteConfirmMs，推荐60秒现实时间，需确认），绑定当前epoch和物理revision；CORRUPT/UNSUPPORTED状态可绑定“全档删除”与null revision。`confirmDelete(token)`需相同实例、未过期、未消费、状态/物理revision未变化，否则CONFIRM_REQUIRED；暂停队列与广告回调，调用clear，成功才关闭当前档、清内存及返回删除完成；不自动恢复旧备份。删除标记以独立规范JSON+SHA256记录generation/allowedEpoch（null表示全部旧槽禁止），写入并重新读取验证后才删除3槽；标记是逻辑删除提交点，即使后续物理remove部分失败，load也不接受旧epoch。若用户明确开启新档，beginEpoch写新allowedEpoch，仅新epoch可读。marker不存在但旧槽存在的情况按普通恢复（无法抵抗恶意删除标记）；marker损坏则fail closed，提示恢复/删除。删除过程中marker写结果不确定先读取核实，不宣称删除成功。允许保留诊断日志但不保存已删除资产内容；删除不包含云存档（P0没有）。清除微信全部数据、卸载、手机丢失无法保证恢复。

裁剪：ledger最近maxLedgerEntries条及recentSettlements最近maxRecentSettlements条，按时间/稳定ID排序保留最新，聚合余额、goldIn/out与终止水位永久；不要依赖已裁剪流水重新推算全部余额。已售普通鱼只有在未被持有、纪录历史、首次捕获、重要事件、未关闭报告引用时才可删档案；先更新聚合及引用后同一事务裁剪。所有重要纪录/首次档案永久保存（容量待实测）；不能擅自裁剪。报告未领取且未过期不得因数量上限清除；已领取/过期按maxClosedReports保留最新，过期报告删除后旧ID不可再领取；active广告引用的报告不得裁剪。一次性claimKeys永久；已结算尝试以连续lastTerminalAttemptSeq去重（不要求所有尝试明细永久保留），广告同理；命令只保留最新receipt，旧序号拒绝；所有裁剪不得改变幂等依据。大容量存档和文件配额实测如不满足，返回SAVE_IO及诊断，待设计负责人调整策略，不自动删重要鱼获。

## 8. 广告接口事务

### 8.1 BEGIN_AD 前置与快照

所有广告由玩家主动选择；`BEGIN_AD`入队校验运行状态RUNNING、SDK可用（AdProvider能力探测由平台提供）、无active request、目标合法、quotaDay未回退。quotaGroup：SPEED、EXTENSION、RESET独立；BAIT用cfg.ads.baitSupply[baitId].quotaGroup，高级共享日上限1；GOLD以reportId一次性键不共享每日次数。配额只在实际奖励成功提交后计入发起日。可显示预览但最终查当前状态。各类型：

| 类型 | 校验 | 锁定字段 |
|---|---|---|
| SPEED | 日次数未满，speedMultiplier>1 | durationMs=配置单次现实时长，锁configVersion |
| EXTENSION | 日次数未满，永久额度+已存临时额度<24h | durationMs=min(配置扩展量,剩余空间)；不可给当前正在补算会话追加 |
| GOLD | report存在、未领、未过期、adRewardGold>0 | reportId及reward=报告锁值，领取资格以发起时为准，仍受请求超时 |
| BAIT | 非基础免费、已解锁且正常可取得、配置供给和配额；库存空间>=1 | reward=min(供给量,剩余库存空间)，预留该库存空间直至请求结束；普通奖励/补货/购买必须尊重这部分预留 |
| RESET | allocated合计>0、日配额未满 | 锁目标类型；播放期间不允许玩家主动改变属性/其他资产指令，钓鱼仍可推进；未分配升级点不影响返还 |

生成id=`epoch:ad:nextSeq`，request.seq=nextSeq，nextSeq+1，状态CREATED、createdAt、expiresAt=createdAt+requestTimeoutMs（配置正数）、quotaDay/group、configVersion/reward/durationMs。完整持久化CREATED后启动平台请求，逻辑状态SHOWING也持久化；同一请求只调用SDK一次。广告播放期间允许正常钓鱼和平台生命周期、只读查询，不接受新的玩家资产命令，返回AD_IN_PROGRESS。超时不扣配额，释放预留；不自动重播。

### 8.2 平台回调处理

AdProvider.show在明确完整观看时返回COMPLETED，提前关闭CANCELLED，失败FAILED；异步回调必须携带原requestId并记录接收有效时刻，内部队列消费。SDK调用错误转换FAILED。重复回调/非当前id/seq<=lastTerminalSeq忽略；禁止UI直接调用成功奖励。接收成功但超过请求expiresAt则FAILED/AD_EXPIRED；若回调在有效期内到达但队列稍晚处理，依据记录的完成时刻判有效，不凭空延长。若已持久化请求在进程崩溃时没有可验证COMPLETED标记，启动时按FAILED关闭，不重播/不发奖；用户可能看完却丢回调，此为纯客户端限制。回调若在后台到达，先按真实生命周期补算/恢复，再处理发奖；权益从实际发奖逻辑时刻起生效，不追溯加速已经结算的区间。应用内部不得把“已观看”当作“奖励已发”。

有效COMPLETED可选择先持久化完整成功记录（状态及completedAt），再在同一队列执行发奖候选；恢复发现COMPLETED必须执行一次发奖而不是重新播放。发奖候选必须将权益、配额、终止水位、REWARDED及金币/库存/属性一并提交；若最终提交不确定按第4节扫描确认，不能再次发同一请求。CANCELLED/FAILED设置终态、lastTerminalSeq、释放预留并持久化，不扣配额，不扣资产。终态记录可保留当前最近一条供展示；开始下一请求前旧请求必须已终止。业务日变化后只保留当前/前一日及活跃请求发起日quota计数，日期高水位不可回退。若时钟在请求期间回退且无法确认有效完成时刻，标失败并记录诊断，不伪造完整回调。

### 8.3 发奖步骤

SPEED：`speedUntil=max(cursor,speedUntil)+lockedDurationMs`，只追加时间，若当前已有效加速则保留ads.speedMultiplier，若无有效加速则锁定请求版本的speedMultiplier；到期后恢复1（新旧倍率不得相乘）；加速仅作用速率，不直接改概率。
EXTENSION：`nextOfflineExtensionMs=min(24h-permanentAllowanceNow, nextOfflineExtensionMs+lockedDurationMs)`，永久额度可能在播放中升级，最终以当前剩余空间封顶；下一次真实离线会话创建时一次性消耗。
GOLD：报告存在且发起时合法、未领；使用锁值，不重算净额；写AD流水、标adClaimed=true；报告过期发生在合法请求播放期间仍可按时完成的回调领取。
BAIT：按锁定reward加库存；预留确保不超stockLimit；若版本变更导致容量缩小，阻止该版本切换直至请求终止，不能吞掉承诺数量；不换金币、不赠特殊竿。
RESET：返还全部allocated到unspent，五项清零，不增加paidResets/freeResetsUsed，下一抛竿生效；无金币扣款。
全部成功更新对应发起日quota（GOLD仅报告标记）、request.status=REWARDED、lastTerminalSeq=request.seq，并按统一事务处理金币统计和合法成就（配置禁止广告专属成就）。AD_UNAVAILABLE/失败不得扣既有收益。

## 9. 配置与存档版本切换

`MigrationApi.migrate(raw,from,to)`逐版纯迁移，旧结构先校验，再每步迁移；步骤不可读取墙钟/随机或发奖，除明确补齐缺失历史字段的可审计迁移。迁移保持epoch、revision语义、重量、体色、拥有权、累计奖励、游标、尝试及RNG；缺少迁移链返回MIGRATION_FAILED。迁移成功写新物理槽，保留原有效槽，不覆盖最后旧备份；失败不改文件。读取未来Schema返回VERSION_UNSUPPORTED。

版本切换顺序：新包在本机可用并通过ConfigApi→读取旧档且解析其引擎/配置→先按旧规则锁定并补算原离线有效区间（用旧版本价格/事件/等级）→推进世界至本次实际恢复时点→候选状态迁移结构并验证兼容（必要的结构读取迁移可在补算前完成，但规则版本不变）→提交新配置生效边界→已存在的attempt及prepare继续使用其cast.version（旧环境版本单独推进）→之后的tryStart使用current新配置；旧尝试结束后旧版本环境状态可移除，但必要配置仍随兼容包提供。新环境同世界锚点、按新版本独立流在切换时初始化；已开始旧尝试使用旧环境投影直到结束。历史捕获档案只读，未售价格取当前有效定义；历史物种/颜色/装备/tier必须保留可解析兼容定义，禁止直接删除导致存档非法。成长需求变动若当前xp达到新版阈值，只在版本切换事务按新规则规范化当前剩余XP并发对应新增等级，不追溯重新计算历史总XP（新增设计建议，需确认）；已发自由点不重算。新成就可根据可验证累计事实一次性补发，现场事件类不可凭空补发。未完成广告请求跨版本恢复时先按旧请求成功记录发奖或失败终止，再切换，防止权益配置丢失；已生效加速保持锁定倍率至到期，新增同类加速只追加时长。缺任一旧版必要包、无法保持库存/tank兼容或迁移失败时VERSION_UNSUPPORTED/MIGRATION_FAILED并保留原档；不按新规则静默重算、截断、强卖或清档。包体留存期限需发布负责人确认，P0推荐保留所有已发布可升级版本，无法负担则先设计明确迁移路径。

## 10. 已知平台限制及验证

本地时钟、广告回调、文件校验不具备服务端权威；修改系统时间、存档及客户端代码仍可能作弊。换机或清除微信数据无法保证恢复；云备份及可信时间P1，权威竞技P2。文件容量、微信文件错误码、广告资格、Cocos命令行/GUI依赖、真实低端机离线性能、BigInt和SHA/模块兼容必须实测。任何BLOCKED保留日志与复现步骤，不允许以Node fake的通过冒充微信真机通过。
