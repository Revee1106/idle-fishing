# BE-000 设计方复查事项

本次没有发现必须先修改产品规则才能修复的 BE 缺陷，也没有确认正式文档相互冲突。以下两项涉及正式兼容性或发布预算，由设计方在对应门禁前决定。T07 的最小实验夹具可直接补做。

## D01 · DESIGN_MISSING · P2 · 正式存档格式的字节级验收样例

- **依据与原文**　v0.2 文档 11 §5：“格式及校验算法待Spike确认。” v0.3-draft 文档 19 的存档章节：“按固定字段顺序序列化 `[magic,format,revision,epoch,payload]` 的UTF-8 SHA-256小写十六进制”。
- **涉及接口与复现**　docs/interfaces/contracts.ts 的 SaveEnvelope 与 game-core/spike/save.ts 的 computeEnvelopeHash。让另一端仅按上述文字重建含引号、反斜线或非 ASCII 文本的 payload 哈希输入；比对 UTF-8 字节及摘要。
- **实际与缺口**　Spike 选择对外层数组执行 canonicalStringify，并对结果作哈希。同一实现的 Node/Web 结果一致。文档给出字段顺序，尚缺经批准的完整输入字节及独立黄金摘要；本次未观察到端间实际冲突。
- **影响及建议**　请决定正式格式是否采纳本实验方案，并发布一组含转义字符的独立向量，说明 payload 字符串在外层的转义规则。后续独立实现和旧档兼容依赖此决定。**不阻塞 BE-000 整改；正式发布存档格式前需确认。**

## D02 · DESIGN_MISSING · P2 · 真机性能预算

- **依据与原文**　v0.2 文档 14 §3 T06：“正式阈值及负载在结果后确认”。
- **涉及接口与复现**　advanceOffline、maxNodes 与 tests/backend/be-000/perf.ts。相同 24h 夹具在 Node 与 Cocos Web 可得到一致终态，Node 可测连续/分片耗时和进程内存。
- **实际与缺口**　当前数值只描述桌面环境；尚无负责人确认的代表设备、负载档次、允许主线程阻塞时长及内存预算。按基线约定，这是留待真机测量后的决策。
- **影响及建议**　联合验证提供代表设备、帧时间、内存、恢复及分片结果后，由负责人和设计方确定正式预算和测量口径。**不阻塞 BE 代码整改；完整 T06 真机性能验收仍待该决定及实测。**
